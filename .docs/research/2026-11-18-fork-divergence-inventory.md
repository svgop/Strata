# Fork divergence inventory (2026-11-18)

## 0. Verdict first

Of the ten headline fork features audited, **four are fully or partially upstream-native now** (cvec project mode — shared since the fork point; the non-finite logits guard — a fork port of upstream work; `--mtp-draft-vocab` subsetting — flag shared, subset ecosystem now upstream; dspark Q8_0 drafter — upstream owns the dsv4.1 dspark line incl. the 0.2.7 Q8_0 markov head), **two are shared lineage where upstream moved independently** (PLE n-gram tables, GSQ packs), and **four remain genuinely fork-only** (STRATA_SHADOW_EXPERTS, the elastic conversation-cache slots + restart persistence, runtime expert-profile learning, and the entire mm3/MiniMax VQ lane). Cherry-pick, do not rebase: the fork carries 96 fork-only `STRATA_*` knobs woven through a tree upstream rebuilt around compiled geometry (306 upstream-only knobs on the other side), and the fork's port-set practice (F-368/F-369) is already proven.

## 4. Recommendation

**Cherry-pick; a rebase is not survivable.** The fork's 541 commits are not a patch series — they are a measured campaign (96 fork-only `STRATA_*` knobs wired through `generate.cpp`/`verify.cpp`/`serve`, launcher fleet, campaign/tracker instruments) and upstream spent the delta rebuilding the engine around compiled geometry (PLE/kernel widths follow the compiled shape, `f3e99e58d`/`f3e99e58d`-class commits) plus 306 new env knobs — replaying fork history onto that tree re-litigates every battery. The fork already runs a proven port discipline (F-368 `231290e9c`, F-369 `fcc45f0a1`): port correctness/serving fixes first, parity-prove each, battery before default. Concrete cherry-pick queue, in order: (1) `git fetch upstream` to close the 787-commit Nov 12–16 blind spot; (2) serve/engine correctness — #4677 stop bound on every backend (`13eedf552`), MMQ row-id margin fixes (`697b6d67a`, `14dd746f6`), penalty window #4590 (`ed76b12f9`), qwen35 penalty OOB #3911 (`6c01f85ad`); (3) conv-cache eviction RAM return #5697 (`8c71c4927`) and the CKPT pool/async opt-ins (`ca378670b`, `f73b3c86a`, `85e3dde52`) — they compose with the fork's elastic slots instead of conflicting; (4) dsv41 router NaN guards (`f6eed469e`, `dc1bc4c34`, `8e8e3cafa`) to finish the non-finite family; (5) evaluate DFlash2 as the one large capability gap (fork's T14B rejection predates upstream's productionization — the contract changed under the verdict). Keep fork-only: shadow store, elastic sessions + T66 persistence, runtime profile learning, mm3 lane — nothing upstream shadows them, and upstream's `--resident-experts` RAM fallback (`43543e9b0`) is the only cousin worth diffing against the shadow store before spending a boot.
