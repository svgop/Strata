# The conditional one-doorbell window (2026-11-09)

## 1. Question

The serial M1 lane pays ~12.27 ms/window of GPU-reach wait (86% of its ~14 ms window; `sweep-diag-pcie90.txt:10`: `21.27 ms/win = GPU wait 12.27 + host 5.10 (CPU 4.21)` at the 8-token leg, `T 3.26 | tok/win 3.03` standing). Pair/conc overlap it to 0.5-0.7 ms. The wait is the per-layer doorbell: the graph rings `m_seq_` once per layer-group (48+/window), the host spins `while (*seq < want)` (verify.cpp:3149 serial, :4550/4581 pipelined), and each miss group's rows are computed on the host between rings. The all-resident zero-doorbell graph exists but is unreachable on this box: it requires `hits.h_res[l*n_expert+e] >= 0` for ALL experts of ALL layers (verify.cpp:1116-1123) — 9,900 of 24,576 slots held. Design the conditional form: rings only for the groups that miss.

## 2. How the zero-doorbell graph works today (the ar_on path, end to end)

- **Gate.** `ar_on() = all_resident_ && !ar_off_` (include/strata/core/verify.hpp:504). `all_resident_` is computed once at verifier init by scanning the host residency table `hits.h_res` for the layer range [lb_, le_) (verify.cpp:1105-1126); `ar_off_` flips per window in `refresh_ar()` (verify.cpp:2525-2539) when a loan/shrink/swap marks any slot -1. On this box the scan fails at init (24,576 experts > 32 GB), so `ar_on()` is false forever and `exec_nr_[T]` (the doorbell family, capture() verify.cpp:2542) is the standing variant.
- **Arming.** The all-resident arm allocates the device slot-offset table `slot_off_d_` (verify.cpp:1153-1162) — a copy of `hits.slot_off`, so the device can resolve an expert's VRAM address from the residency table alone.
- **pre(l) under ar_on** (verify.cpp:2093-2096): `resident_plan(...)` runs ON DEVICE — one 128-thread block (verify_kernels.cu:1511-1617) reads the routed ids `ids_` (device, written by the router in pre(l) at verify.cpp:2061-2078), reads the device residency table `d_res`, and builds the whole plan in DEVICE memory (`plan_ + grp*stride`): group starts, dst/tok lists, and the expert blob pointers `ptr[grp] = cache_base + slot_off[slot]` (:1589). It writes `skip_` = the ring value (:1612-1615) as the "no host needed" marker. NO doorbell publish, NO mapped staging, NO host involvement. `skip_` is a 64-B device word-per-(layer,group) table (verify.cpp:1156).
- **post(l) under ar_on** (verify.cpp:2236-2239): the grouped expert GEMM reads the device plan directly (`grouped(p_ptr, p_start, p_counts, 0, parts_out)`); every pick is a VRAM hit, so there is nothing to wait for. The only host interaction left in the whole window is the PLE staging flag (verify.cpp:1340 `wait_flag_ge(m_flag_, 1)`), which the host raises once at window start (run() verify.cpp:3129-3139: gather PLE rows, `*flag = 1`).
- **The graph itself.** Straight-line capture of pre/post for all layers (record_window, verify.cpp:2378-2384). `STRATA_WINDOW_GRAPH=1` (verify.cpp:244-259, LANDED default-off at 1465fa6b) wraps it as ONE conditional WHILE node: root graph → `cudaGraphConditionalHandle` (init 1, `cudaGraphCondAssignDefault`) → conditional node → body populated by `cudaStreamBeginCaptureToGraph` around the UNCHANGED `record_window` → `win_cond_tail` kernel zeroes the handle after one pass (verify.cpp:2551-2621). Wrap gate: `wrap = g_window_graph && ar_on()` (verify.cpp:2554) — INERT on this lane. Legality probe-verified on this rig: the shared-expert fork folds to plain edges, zero event nodes; kernel/empty/memcpy/memset/child/conditional whitelist holds (2026-11-06-condgraph-package.md §3).
- **The host under ar_on** (run() verify.cpp:3129-3139, service() :4568-4575, batch_serve() :4191-4195, batch_poll() :4275-4279): stage PLE rows, raise flag 1, done — the window is ONE `cudaGraphLaunch` (HostGraphLaunch off-thread, `STRATA_VERIFY_ASYNC_LAUNCH=1` armed) and the host waits for graph completion.

**The load-bearing fact:** zero-doorbell does not come from a magic kernel — it comes from (a) the plan being buildable on device from `d_res` + `ids_` (both already in VRAM when pre(l) runs) and (b) every wait being skippable by a device-written word (`skip_`). Both mechanisms exist TODAY and both already run on the doorbell lane: `STRATA_VERIFY_DEVICE_PLAN=1` is armed standing (launch-custom-iq3s-8081.sh:24), so a miss-free group's `skip_[grp] = ring` already skips `wait_flag_ge_planned` (flagA), the plan D2H copy (`copy_i32_from_mapped_unless`, verify.cpp:2247), waitB, and zero-fills the CPU-rows copy (`copy_rows_or_zero_from_mapped`, verify.cpp:2299). What standing E-6 does NOT skip: the ring itself (`doorbell_publish_res` fires for every group), the host wake (the host spins up, finds `h_flagA_ != want`, publishes an empty plan and raises flags for a group the GPU never reads — verify.cpp:3214-3223), and the publish kernel's PCIe work.

## 3. Why partial residency blocks it — and why the static pre-serve is impossible

- **The ring's role.** `doorbell_publish_res_kernel` (elementwise.cu:329-351) runs in pre(l) after the router (:2121-2125 standing): it copies ids/w to mapped staging ALWAYS (:335), copies the activations xm ONLY when a routed id misses (`__syncthreads_or(any_miss)`, :338-340 — the conditional-publish precedent already in-tree), and then rings `m_seq_` UNCONDITIONALLY (:344-349, one PCIe RMW). The ring is the host's progress signal AND its serve schedule: the serve loops assume ring k names the k-th group in order (`want = fl_k_ + 1`), which holds only because every group rings.
- **What the host must do per miss group.** Wake from the `_mm_pause` spin, read `h_ids_` (mapped), classify every (token, expert) entry against `h_res` (expert_source.cpp:4694), build the plan (distinct experts, VRAM/CPU/PCIe kinds), publish it to `m_plan_` + flags, and compute the CPU rows into `h_ymiss_` (pool callback, verify.cpp:3197-3199). This is `pool()`; its per-window wall is the "CPU" telemetry term (2.13 ms/window standing at T≈3.3, 4.21 at 8-token windows).
- **The static variant fails on three independent grounds.** (1) Routing is device-side and SEQUENTIAL: the router GEMV + top-10 of layer l consume layer l's mixer output, which consumes layer l-1's combine output (verify.cpp:2047-2078; stream order pre(0) post(0) pre(1) post(1)...). The routed set of layer l does not exist in the universe until layer l's pre executes inside the window. (2) The rows themselves depend on xm — the activations the publish stages — which likewise do not exist before the layer runs. "Serve ALL CPU-miss rows up-front" is not early host work; it is future GPU work. (3) The 'plan'/'actq'/'jobs' telemetry (generate.cpp:16857) is the POOL's per-ring accounting (d.ms_actq, expert_source.cpp:5107), not pre-window routing knowledge; `STRATA_PREDICT` (launcher: `STRATA_PREDICT_CREDIT=1.0`) predicts routed sets only to PLACE experts in the cache tiers and prefetch blobs (expert_source.cpp:853, 974-1012) — it publishes no per-window routed table and cannot conjure rows. **Conclusion: the design lands on the task's second branch — rings only for the groups that actually miss, decided on device inside the graph.**

## 4. The design: STRATA_COND_RING=1, one launch per window, rings only for miss groups

All new behavior behind ONE env (`STRATA_COND_RING`), default off = byte-identical standing path. It composes three in-tree mechanisms (E-6 device plan, T1.1 partial skip, the landed conditional wrapper) with one kernel change and one serve-loop change.

- **C1 — the conditional ring (the kernel change).** New `doorbell_publish_cond_kernel`: exactly `doorbell_publish_res_kernel` (elementwise.cu:329-351) but the `seq` store moves INSIDE the `any_miss` branch and uses the STORE form — `*seq = ring` with `ring = (l-lb_)*G+grp+1` passed as the capture-time constant `value`, exactly `doorbell_publish_value_kernel`'s store (elementwise.cu:362-366; #649 proved the capture-known constant store on CUDA). Miss-free groups: no mapped write at all, no fence, no PCIe RTT, no host wake. Miss groups: one store of the ABSOLUTE group index. `m_seq_` semantics change from "ring count" to "index of the latest ringing group" — monotone along the stream (each pre(l) is stream-ordered after post(l-1)), reset to 0 per window at staging (verify.cpp:2899). Wire at verify.cpp:2121-2125 as the new first branch of the standing publish conditional. `d_res`+`ids_` give the same miss answer resident_plan computes (same stream order, resident_plan runs first at :2103-2108; d_res is immutable mid-window), invalid ids count as miss (:336) so the s_bad host-fallback still rings.
- **C2 — miss groups take the T1.1 partial route.** The mode forces `plan_partial` semantics (verify.cpp:2102-2108, `partial_skip = kPlanPartialSkip = 0x80000000`, verify_kernels.hpp:166): a miss group's resident entries are device-planned (`skip_ = kPlanPartialSkip`), the flagA/flagB waits skip (`wait_flag_ge_planned`, verify_kernels.cu:1442), `counts[2]=0` zeroes the PCIe share (:1611 — standing lane has no PCIe share anyway; pin `--pcie-frac 0` for the A/B per the T1.1 protocol), and only `m_flag_` (the CPU rows) is waited (`wait_flag_ge_or`, skips only a full plan, verify_kernels.cu:1464). The host's remaining job per miss group is EXACTLY the pool row compute + `*flag = want`. The armed `STRATA_DM` fold composes: `dm_wait_combine` carries the same guard (verify_kernels.cu:1694/1701; verify.cpp:2289-2300, 2343-2345).
- **C3 — the serve loops key off the absolute ring index.** In run() (verify.cpp:3141-3239), service() (:4542-4629), batch_serve() (:4185-4235), batch_poll() (:4237-4299) and run_slot_rows (:3946+, b_k_ loop at :4202-4232): replace `want = k+1; while (*seq < want)` with `if (*seq <= served) <wait>; else { k = *seq - 1; l = lb_ + k/G; grp = k%G; serve(l, grp); served = *seq; }`. Ring values arrive strictly increasing with gaps at miss-free groups; the loop never sees them. The empty-plan publish for device-planned groups stays in v1 (harmless: the GPU's `copy_i32_from_mapped_unless`/`wait_flag_ge_planned` skip on `skip_`, :2241-2247) — v1 changes the INDEXING, not the host's per-ring work.
- **C4 — exit and watchdog semantics.** A window with miss-free groups never reaches `*seq == steps`, so the loop exit becomes: graph done (`launch_o->query()`, verify.cpp:3156 / service() :4585) AND `served >= *seq` → clean completion. NEVER-RANG (verify.cpp:3160-3166, :4586-4591) fires only on graph-done with `served < *seq` (a ring the host never served — a real defect); the 2 ms WDDM flush cadence and the 20 s no-progress watchdog (:3153, :3168, :4583, :4594) key on `served` and survive unchanged. A fully miss-free window exits with zero rings — the loop is then pure "wait for graph-done", i.e. ar_on's host shape.
- **C5 — PLE leaves the first ring's critical path.** Today the gather rides the `k==0` serve (verify.cpp:3228-3234, :4626). In the new mode layer 0 may not ring, so gather BEFORE/AFTER launch unconditionally and raise `*flag_ = 1` immediately (the ar_on branch's exact shape, :3129-3139); the graph's pre(1) copy at :1338-1342 needs no wait in doorbell mode (the copy is unconditional at :1341; pre(1) is stream-ordered behind post(0), which no longer depends on a ring-0 wake). This also deletes a hidden serialization standing today.
- **C6 — wrap both graph families.** `wrap = g_window_graph && (ar_on() || cond_ring_on())` at verify.cpp:2554: `exec_nr_[T]` (the standing doorbell body) gets the same conditional WHILE wrapper as `exec_[T]`. Legality is probe-proven for the doorbell body: its waits/publishes are kernel nodes, the fork folds to edges (2026-11-06-condgraph-package.md §3 and its §6 remainder, which names exactly this increment). `win_cond_tail` (one pass per replay) is unchanged. `STRATA_VERIFY_NODES=1` re-lists the body as the boot-time check.
- **C7 — the usage histogram must move to device (the hidden dependency).** The pool's per-ring call feeds `d.usage` (expert_source.cpp:4631-4633) — the routing histogram the placement/predict machinery eats to hold the 98.8% hit rate. Zero rings on miss-free groups starves it. Fix inside the mode: `resident_plan_kernel` already holds the routed ids — add an atomicAdd histogram into a device word-per-expert buffer, drained once per window by the host (one small D2H at window end, off the critical path). Without C7 the complement DECAYS and the whole design self-defeats; it is a required component, not an optimization.
- **C8 — refusals (copy device_plan_'s gate discipline, verify.cpp:1140-1142).** The mode is refused with `always_publish_` (pipelined multi-GPU — publish must fire), `remote_opt_` (helper-GPU PCIe share), `m_bal_` (pcie balance stamps), `prof_on_`/`g_dmws.live()` (the instruments stamp sites the mode deletes — the same rule as the dm_fold gate at :2230-2231), and `test_stall`. On refusal: boot line + standing path.

## 5. Pricing (honest, against the measured decomposition)

- **What the 12.27 actually is.** F-220's mechanism correction (SVG-CUSTOM.md, T1.1 entry §5) is the law: the GPU-reach wait is the GPU's serial window execution wall as seen by the spinning host, NOT host round-trips — the flagA plan RTT the T1.1 arm deleted measured **~0.26 ms/window total**, and the pool's CPU-row compute (~2.1-4.5 ms) is a SEPARATE additive segment tiled against the GPU's `m_flag_` stalls. The doorbell machinery's contribution to the 12.27 wall: 48 publish kernels (~3-6 µs each: ids copies + `__threadfence_system` + PCIe RMW ring) ≈ 0.15-0.30 ms; ~144 wait-node dispatches at ~2.4 µs/node class ≈ 0.25-0.35 ms; 44 plan-copy node dispatches ≈ 0.05 ms; miss-group flagA RTT ≈ 0.26 ms. **Total doorbell class ≈ 0.7-1.0 ms/window.**
- **The needle.** C1+C2+C6 delete the publish work, the ring RMWs, and (with per-group IF conditional nodes, CUDA 12.4 semantics already in-tree) the wait/copy NODE DISPATCH for miss-free groups: **~0.5-1.1 ms off the ~14 ms window = solo +4-8% (207 → ~215-225)**. At N_miss ≈ 5% of groups (the inventory's 99.5%-slot-hit estimate) the savings sit at the low end (mostly node dispatch); at N_miss ≈ 50% of groups (60 picks × 1.2% pick-miss rate) they sit at the high end.
- **The 12.27→~2 telemetry claim is real but it is the HOST's clock, not the window's**: ms_wait (verify.cpp:3237) collapses because the loop stops walking 48 rings and waits on graph-done; the host also stops publishing empty plans and raising dead flags (~1-1.5 ms host work/window freed). That is host-capacity and power, and it is what protects pair/conc — not a solo window win.
- **Solo ~260+ is the composed upper class, not this arm's deliverable.** Window 14 → ~11.5 ms additionally needs the serialized pool segment off the critical path (~2.13 ms; physically irreducible on the serial lane — rows need xm — this is what pair/conc already overlap, and what chain_overlap/T9.C#2 pipelining attacks) plus the dense/hc/attention compute fusion (W5/W6/W13, F-220's own "shrink the 16.4" list). Law 15 framing: this arm's priced needle is the 0.5-1.1 ms doorbell class; the rest is named, not claimed.
- **Pair/conc.** The rings are the mechanism, not the benefit — the lanes overlapped the ring work, they did not profit from it. Both lanes take the same 0.5-1.1 ms window cut, lose the cross-lane host wake contention (~48→N_miss wakes/lane/window), and keep their pool overlap. Risk concentrates in the serve-loop rewrite touching the conc/batch loops (C3), not in the mechanism.
- **Boot cost.** Wrapper: +2 nodes × 8 T-families × 2 graph families — negligible; capture time unchanged; one device histogram buffer (C7, n_expert × 4 B = 96 KB) + no new mapped regions. `cond_node` (bench/micro/cond_node.cu) prices the conditional dispatch delta before any boot.

## 6. Risks

1. **The serve-loop rewrite is the blast radius.** Four loops (run/service/batch_serve/batch_poll) + run_slot_rows share the ring-count assumption. Mitigation: env-gate every loop body (standing path byte-identical with the env off); the conc/batch loops get their own A/B legs; `STRATA_TEST_VERIFY_STALL` (verify.cpp:3128) and the trace breadcrumbs exercise the never-rang/watchdog paths.
2. **m_seq_ semantic change is process-wide.** diag/trace readers (verify.cpp:636, :698, :4444) and any future code assuming consecutiveness must read the new contract; document at the `stage_inputs` reset (:2899) and in verify.hpp next to `ar_on` (:504).
3. **Complement decay if C7 is skipped** — the usage histogram starvation silently degrades the 98.8% hit rate over sessions. C7 is mandatory; its drain cost (~96 KB D2H/window) rides the existing commit boundary.
4. **Empty-plan publish waste (v1)** — the host still writes a plan nobody reads per served miss group. Harmless by the skip guards; v2 trims it with a per-window device miss-mask readback if the miss groups are frequent enough to matter.
5. **T1.1's own verdict is a warning, not a blocker**: partial plan ALONE closed neutral (-0.6/-1.6/-0.9, F-220) because it removed only the 0.26 ms plan RTT. This arm differs by deleting the ring/wake/dispatch class on miss-free groups AND the host loop — the parts T1.1 did not touch; if the composed arm lands inside the drift band (180-222) on every lane, it dies at the kill line with the pricing recorded (law 15).
6. **Device/host residency skew mid-window** — the #871 class (verify.cpp:3285-3290): d_res says resident, cache moved. Standing E-6 already carries this exposure for miss-free groups; the mode adds nothing new, but `h_plan_err_`-style containment stays out of scope (device_plan_ groups run without it today).
