# What bought the +25% batched-decode win in v0.2.9..v0.2.10

## Scope facts fixed first

- The 6-conc window on this config is a **plain batch window**: `--batch 6`, no `--batch-mtp`, no DFlash2. Each active slot contributes exactly **1 row** (its current token); a round is one `run_slot_rows` over 6 rows, greedy argmax off the window head, `commit_slots`, no per-slot drafting. Window graph kind: **doorbell graph with CPU/PCIe experts** (partial residency, `--pcie-frac 0.35` explicit, `--pcie-mode dma`), not the all-resident graph.
- The CUDA Linux build is the 8-row narrow build (`kVerifyMaxT == kVerifyNarrowT == 8`; CMake `STRATA_WINDOW_MAX_T=auto`; the 0.2.10 diff only adds a 12-row option, default unchanged). So the batch window at 6 slots takes every exact-T kernel at **T=6**.
- `STRATA_GR_V3` (the staged hyper-connection read) was already the default read on sm_120 >13 GiB in v0.2.9 (confirmed in a 0.1.45-era start log: "the hyper-connection read runs as staged"). Only its load-ordering variants are new.

## Ranked mechanisms

### 1. `STRATA_GR_V3_PF=133` — new default-on sm_120 switch; bit 7 is the ONLY conc-gated hunk in the whole diff

- New file `include/strata/core/bw_dense_defaults.hpp` (did not exist in v0.2.9): `gr_v3_pf_default()` returns **133** on a CUDA compute-capability-12.0 card (off under `STRATA_DEFAULTS=026`; `STRATA_SM120_PERF=0` also kills it). `STRATA_GR_V3_PF` does not exist anywhere in v0.2.9 (`git grep` empty).
- Implementation entirely in `src/kernels/cuda/fused_gr.cu` (v0.2.10 lines ~2665-2990): `v3_pf_mask()` reads the default per device; dispatch in `fused_gr_read_multi_slice` at `split == 2`:
  - **bit 7 (128): `gr_down_rb_dispatch_k<2>` — register-blocked gr_down, 2 rows a warp, gated `n_tok >= 5`.** In-tree measurement quoted in the header: "down 16.1 / 16.2 / 17.6 / 19.5 -> 13.3 / 14.1 / 14.7 / 15.6 us at T 5-8" (DF2-MORE campaign, RTX PRO 5000). At our T=6 that is **−13% on the down kernel, every layer, every round**. Windows of T<=4 are untouched by construction — which is exactly why the pair lane (~195) and the solo lane (MTP windows average T≈2-4 under `--spec-min-p 0.5`) read unchanged.
  - **bits 0+2 (mask 5): gr_down "staging loads of every token in flight together" + gr_up "partial sums and per-row inputs loaded before use"** — all T; in-tree: "5 (= down 1, up 1) is 4-8% faster at T 1-8 (T4 26.45 -> 24.90 us)". Bitwise identical outputs (gr_v3_screen: 0 differing, T 1-8).
- Why it lands hardest at 6-conc: the 6-row window is the compute-dense case (6 rows share one expert pass; the ~60-expert union has a higher resident hit-rate per token than a solo row's 10, so the 0.35 PCIe miss share hides less compute). Solo windows are stall/launch/drafter-bound, so all-T micro-wins sit in noise there; bit 7 cannot fire at all below T=5.
- Portability to a fork whose single-card window is v0.2.7-era: the v3 kernels themselves are already there; the PF/RB variants are **additive template parameters + one dispatch branch + the `bw_dense_defaults.hpp` default**, all self-contained in `fused_gr.cu` (+2-line header). Direct copy is clean.
- Registers: the RB `<1,6,true,2,0,true>` instance keeps 8 bytes of spill (upstream `tools/check_cuda_spills.py` documents and tolerates it) — expected, accepted.

### 2. `STRATA_SMALL_UNR=3` — second new default-on sm_120 switch (same new header)

- `small_unr_default()` returns **3** on sm_120 CUDA. `STRATA_SMALL_UNR` absent from v0.2.9.
  - **bit 0 — the bf16 router read**: `mmvf_fast()` threads through `bf16_f32_mmvf_multi_kernel` (`src/kernels/cuda/native_bf16.cu`); the router GEMV (n_embd -> 512) runs batched over the window's rows with constant-trip load loops.
  - **bit 1 — the GDN a/b projection**: `gdn_ab_body(..., int fast)` in `src/kernels/cuda/verify_kernels.cu` (n==2560): the ten passes become a constant-trip unrolled loop so weight and activation loads of several passes issue before the first FMA chain; "bitwise the loop below". Flash-Next's GDN layers are ~3/4 of the stack, one a/b projection per layer per window.
- Conc asymmetry: fires at every T, but the same compute-density argument as above applies; the multi-row instantiations are where the load scheduling pays.
- Portability: two self-contained kernel patches (`verify_kernels.cu`, `native_bf16.cu`) + the default row.

### 3. The doorbell expert path fuses SwiGLU + Q8_0 quantize (`src/kernels/cuda/s2_expert_grouped.cu`)

- New `launch_hit_swiglu_q8()`; the three hit variants `moe_hit_grouped_s2`, `moe_hit_grouped_s2_dev`, `moe_hit_grouped_s2_multi` now take the fused kernel. In v0.2.9 the fusion existed only in `grouped_s2_impl` (the all-resident path); **the hit path — which is what a partial-residency doorbell graph runs for the resident experts ("R4 hit path ON") — did swiglu_kernel + quantize_q8_0 as two launches**. Default on (`STRATA_S2_SWIGLU_Q8`, unset = on).
- Saves 2 launches + one extra read/write of `cap_entries x FF` floats per layer per window (~48 layers). A few percent of a 6-row window at most; part of the stack, not the headline.
- Also in the same file: `gu_grouped_t_kernel<0, 1>` / `down_grouped_t_kernel<0, 1>` MAX_E=1 variants (≤16-entry groups: the MTP drafter's single token) — drafter-side, not our batch delta; `s2_sync_lds` is gfx12-HIP only.

### 4. `copy_i32_from_mapped` goes multi-block (`src/kernels/cuda/elementwise.cu`)

- Was `<<<1, 128>>>` (one block striding the whole mapped read — PCIe-latency-bound); now a grid-stride launch (up to 64 blocks x 128 threads). This copies the **device plan** (`copy_i32_from_mapped_unless(pl, m_plan_ + grp * plan_i32_, ...)`) in every doorbell-graph expert group, every layer. Solo benefits equally in principle; visible only where the plan copy is on the critical path (bigger windows). No env switch — needs a rebuild to A/B.

### 5. Residual candidate if the switch legs do NOT recover the gap: the binary, not the source

- In-tree measured values for items 1-3 sum to roughly 3-6% of a 6-row window, not 20%. If `STRATA_GR_V3_PF=0 STRATA_SMALL_UNR=0 STRATA_S2_SWIGLU_Q8=0` on 0.1.56 reads ~270-280 (partial recovery), the switches are real but co-drivers; if it still reads ~315, the delta is in the **build**: both tags ship `cuda13` and `cuda12` Linux variants (packaging/ENGINE-COMPONENT.md — `build_id` literally embeds the toolkit, e.g. `<commit>-cuda13.0`). A 0.1.55=cuda12 vs 0.1.56=cuda13 swap would move every sm_120 kernel's codegen and would masquerade as a source-level win. Check `BUILD.json` / `build_id` in both engine install dirs before trusting any source attribution.

## Ruled out (each with the exact gate)

- **DFlash2 batch slot drafts**: `batch_df2_wanted` requires `o.draft == "dflash2"`; single card is opt-in `STRATA_BATCH_DF2=1` only. Config passes no `--draft`; off.
- **CPU/PCIe miss-share start change** (`STRATA_PCIE_START`, E26): guarded by `o.pcie_frac_auto && o.pcie_probe_gbps > 0.0`; explicit `--pcie-frac 0.35` makes `pcie_frac_auto` false in both versions. Dead code on our legs.
- **PDL**: v0.2.9 `pdl_supported()` was env opt-in (`STRATA_DF_PDL`) — off by default, so no window graph had PDL. v0.2.10 defaults it ON for sm_120 but the recorder restricts it to `(STRATA_DF_PDL set || (ar_on() && !batch_rec_))` — **all-resident solo graphs only**. Our doorbell graphs (batch and solo) have no PDL in either version. The v0.2.10 comment states the reason: PDL measured "+0.3..+0.5% all-resident; −1.6%..−4.5% in the doorbell graph".
- **`--lookup-max-t` default 12**: `default_lookup_max_t()` returns 0 when `o.batch > 1`. Off on our legs; all its plumbing (kVerifyLongT, chunked head, graph_fits) is dormant.
- **MMQ_KQ / K-quant experts**: irrelevant — experts are IQ3_S; and no MMQ change touches the IQ hit path.
- **EXPDEC default flip**: the "enabled by default on gfx12" change is applied only via `arch_default_env` (HIP tables). `expdec_mode()` on CUDA is `env_on("STRATA_EXPDEC")` opt-in in **both** versions. Unchanged.
- **STRATA_QFUSE / q8_1-fused GR read / shared-expert `x_q8_1` reuse**: `g_qfuse()` is env opt-in in both; `mtp_qfuse_hc_on()` is gfx12-HIP only; the shared expert's q8_1 reuse is wired only from the drafter (`nsw.x_q8_1 = xq_` under `q8_mlp && T == 1`, HIP-gated upstream). Dead on CUDA sm_120.
- **`STRATA_SIDE_MIXER=2` added to nv_defaults.cpp**: that table row is the **sm_121 (GB10)** branch. sm_120 has had SIDE_MIXER=2 via `g_side_mixer()`'s `sm120_default` fallback in both tags (verified identical function bodies).
- **`STRATA_IL_PAD` (5 IQ4_XS columns as 6)**: the output head here is Q5_K; IQ4_XS-only. `MAX_NCOLS` and case-9..16 plumbing is wide-build/lookup-only.
- **QSA changes** (`qsa_select.cu` simt2/alt-min, `qsa_prompt_attn.cu` TRIM/RPF/GATE): all AMD-gated (gfx103x community default, gfx12 WMMA) or HIP-only. CUDA decode attention untouched.
- **iq_kernels.cu (+115)**: `iq_sync_lds` (gfx12 asm), EXPDEC gating refactor, GB10 mode 8, `ed_stage_entry` int4 rewrite (EXPDEC kernels — off on CUDA). sm_120 CUDA expert dot kernels unchanged.
- **MTP drafter changes** (`mtp.cpp`): prompt room (STRATA_MTP_ROOM_MIN, opt-in), `draft_long` (lookup plumbing), multi-copy unification (CUDA already had it), qfuse head views (HIP). In plain batch mode the drafter is idle anyway.
- **`STRATA_DMA_BATCH`**: default 0 in v0.2.10 (docs/BATCHED_DMA.md: "The default is 0, retaining the existing per-expert copies"); both legs run per-expert DMA copies.

## Task item: spill/fit_start commits (2e7db84b, fd818c7b, ecf7424b)

**No effect on this box/config.** All four engine-side "SHORT OF VRAM" gates in generate.cpp are threshold-guarded and stay dormant on a 32 GB card with this margin: (a) drop-the-MTP gate fires only when free < layer+head+~1.8 GiB (~3 GiB) — free is ~15-20 GiB; (b) tight 16-slot loan and own-prompt-buffers gates fire only when `expert_cache < min_slots`; (c) head-to-host gate fires only when the cache sized to 0 slots; (d) `AUTO NO-BORROW` (Linux CUDA, batch>=2) additionally requires `sized_slots.size() == profile.size()` — the card must hold EVERY profiled expert; at 262K with six ~0.73 GiB sessions the cache (~6-8K slots) is far below the 24,576-pair profile. The "KV window floor 4096" is the Python fit_start planner's floor for tiny cards; it does not resize anything at 32 GB. Expert-slot count at decode time is unchanged between the versions.

## Task item: split-engine code-sharing assumption — VERIFIED

- The split engine is a separate binary: `STRATA_BUILD_SPLIT` (OFF by default), own CMake (`src/split/CMakeLists.txt`), own entry (`src/split/tools/sfnx.cpp`). `git grep` confirms **no include of `src/split` headers from src/core, src/program, src/kernels or include/strata** — the single-card serve path shares zero compile units with it.
- The kernels the single-card window runs live in `fused_gr.cu` / `s2_expert_grouped.cu` / `verify_kernels.cu` / `iq_kernels.cu` directly. The DF2-MORE measurements that chose bit 7 were single-card engine measurements (l620 / RTX PRO 5000), not the split engine. Conclusion: the win is not split-engine code; at most the split work shared the same measurement campaign and kernel files.

## Verification plan on our box (cheap, env-only, 0.1.56)

0. First record `build_id` from `BUILD.json` of BOTH installed engines (0.1.55 and 0.1.56) — if the toolkit field differs (cuda12 vs cuda13), weight item 5 up and re-pin the A/B on same-toolkit builds before believing source attribution.
1. **Smoking gun (single leg):** rerun the 6-conc leg on 0.1.56 with `STRATA_GR_V3_PF=0` (the header comment documents: "STRATA_GR_V3_PF=0 restores the plain kernels"). Prediction if item 1 is the mechanism: aggregate falls from ~315 toward ~253-270; single/pair legs stay ~190/~195 (they never took bit 7, and lose only the small bits 0+2 share).
2. **Bisect the conc-specific share:** `STRATA_GR_V3_PF=128` (bit 7 only) vs `132` (bits 0+2, no bit 7) vs `133`. The T>=5-gated drop between 132 and 133 at 6-conc, with pair lanes flat across all three, is the conc-specific signature. `STRATA_SM120_PERF=0` is the wider hammer (kills the whole sm_120 set incl. the 0.2.7-era switches — use only if the targeted legs disagree with each other).
3. **Second stack:** `STRATA_SMALL_UNR=0` (expect a few more t/s off at 6-conc, pair barely moves) and `STRATA_S2_SWIGLU_Q8=0` (expect small). Legs 1-3 compose additively; sum them before concluding.
4. **Cross-check the graph kind** in the 0.1.56 start log: no "STRATA_BATCH_DF2: N slot drafters" line, no "short of GPU memory" lines, no "lookup-max-t" line, and the cache slot count printed by `expert cache auto:` identical between the 0.1.55 and 0.1.56 starts. Any drift there invalidates the comparison before kernels matter.
5. If legs 1-3 recover less than half the gap and build_ids match: the remaining delta is per-window host time or an uninstrumented path — next probe is `STRATA_LAUNCH_PROBE=1` plus the batch timing lines (bt_run/bt_commit/bt_emit deltas between versions), not more diff reading.

## Bottom line

The diff contains exactly **one conc-gated mechanism** — `STRATA_GR_V3_PF` bit 7, the register-blocked 2-rows-a-warp `gr_down_v3_kernel` dispatched only at `n_tok >= 5`, in `src/kernels/cuda/fused_gr.cu` with its default from the new `include/strata/core/bw_dense_defaults.hpp` — plus two all-T bitwise load-ordering sets on the same header (`GR_V3_PF` bits 0/2, `SMALL_UNR` bits 0/1) and two doorbell-path micro-changes (hit-path SwiGLU+Q8_0 fusion, multi-block mapped-plan copy). The in-tree per-kernel numbers for these sum short of the measured +25%, so leg 0 (build_id parity) and leg 5 are mandatory before closing: the honest split is "GR_V3_PF bit 7 is the conc-specific source-level mechanism; residual magnitude to be confirmed by the switch-off legs and the toolkit field".
