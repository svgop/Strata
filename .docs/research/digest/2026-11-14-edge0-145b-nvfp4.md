## 2. Artifact / format — header-verified

Repo = 105.12 GiB total ([tree API](https://huggingface.co/api/models/Edge0/Edge0-145B-NVFP4/tree/main?recursive=true)). **Not safetensors — a Strata pack** (`pack_format: "strata pack index v3"` in model.json). Inventory + verified layout:

| File | Size | Verified content |
|---|---|---|
| `experts.bin` | 47.56 GB | **Per-expert records: 48 layers × 512 blobs × 1,935,376 B** (512×1,935,376 = 990,912,512 B/layer ×48 = file size exactly). Record = A-only latent expert (gate+up+down at ℓ=1792→640): 3,443,200 params × NVFP4 0.5 B + block scales ≈ 1.94 MB ✓. `native_experts.txt` ("strata native experts v6: latent A-only (expert_embd 1792, expert_ff 640)") indexes every layer: `layer gu_type d_type offset blob_bytes` with **gu_type=d_type=40** (the NVFP4 code) |
| `model-skeleton.gguf` | 5.99 GB | GGUF v3, arch `qwen4exp`, 1079 tensors — **full tensor-info list parsed**: `token_embd`, `output`, `output_hc_*`, per-layer `hc_*` (BF16), `attn_qkv` [2560,10240] Q8_0, `attn_gate` [2560,6144] Q8_0, `ssm_*` (F32/BF16), `attn_q` [2560,12288] Q8_0, `attn_k/v` [2560,512] Q8_0, `indexer.q/k_proj`, `ffn_gate_inp` [2560,512] **BF16 router**, shared expert `ffn_{gate,up,down}_shexp` [640/2560] Q8_0, PLE key/value/conv. Type histogram: 302×Q8_0, 484×BF16, 292×F32, 1×F16; `general.file_type=7`. **ZERO fused `ffn_*_exps` tensors — experts exist only as per-expert records in experts.bin** |
| `ple-fp8.gguf` | 51.2 GB | GGUF v3, arch `strata-ple`, single tensor `per_layer_token_embd.weight` [160 × 320,001,536], FP8 E4M3 with one global scale (`strata.ple.scale=0.000199…`), `source: nvfp4-src` — header-verified |
| `latent_dense_q8.bin` / `_q4.bin` | 3.74 / 1.85 GB | Per-layer D/U projection packs: D=[8×1792, 2560], U=[8×2560, 1792] per layer (8 groups) — Q8_0 file = 2× Q4_0 file size, matches shape math exactly. Selected by `STRATA_LATENT_DENSE_FMT` (8 or 4) |
| `dense.bin` + `index.txt` | 1.43 GB + 117 KB | `index.txt` = "strata pack index v3 — generated by tools/iq_pack.py": pool 1,538,625,024 B (= dense.bin byte-exact), 1367 tensors, rows `name kind ? offsets… 512 …` — names carry the fused-source naming (`blk.N.ffn_{down,gate,up}_exps.{scale,input_scale}`, per-expert dim 512) for the NVFP4 scale tables; dense tensors are served natively from the skeleton GGUF per the [pack tool docstring](https://github.com/Edge0-AI/Edge0/blob/main/edge0-strata/tools/iq_pack.py) |

| `profile.bin` | 196,632 B | static expert ranking for residency (`--expert-profile`) |
| `mtp/` | 0.77 GB | MTP draft layer: dense.bin 116 MB + experts.bin 707.8 MB (512 experts × 1.375 MB, 1 layer) + draft_vocab.bin; spec window `--spec 4`, `--spec-min-p 0.5` |
| `tokenizer/` | 13.3 MB | Qwen-family BPE (vocab.json + merges.txt + chat_template.jinja) |

**Loads in stock llama.cpp? No.** No published GGUF single-file exists; the GGUF-arch is `qwen4exp` (custom), the pack needs the Strata loader (`--pack` + `--native` + `--ple-gguf` + `--expert-profile` + `--mtp`). A third-party conversion exists ([infosave/Edge0-145B-cmf](https://huggingface.co/infosave/Edge0-145B-cmf) for a Rust "cortiq" engine) — card says routed experts are NVFP4-copied, D/U+shared re-encoded 8-bit, router 16-bit; not llama.cpp either.

**"47.79 GiB weights" decomposes exactly** (my math): experts.bin 47,563,800,576 + latent_dense_q8 3,743,416,320 = 51,307,216,896 B = **47.79 GiB** ✓. Engine footprint on 24 GB card (card-attested): 23.25 GiB VRAM + 38.27 GiB host RAM with residency on, disjoint expert sets.

## 3. edge0-strata — what it is (file-anchored)

Per [edge0-strata/README.md](https://github.com/Edge0-AI/Edge0/blob/main/edge0-strata/README.md) and [EDGE0.md](https://github.com/Edge0-AI/Edge0/blob/main/edge0-strata/EDGE0.md):

- **A fork of Niko1221/Strata** (MIT, copyright Niko1221 and Strata contributors), imported at commit `f1933b1e4993fecc10d2e9360d85569619a2c42d`; **merge base with upstream = `c62d5e3a15b40ea51c96aae9e8d36928965f53ab` (2026-10-31)**. Vendors ggml from **llama.cpp `3cf03257f219afbe7334045ff7c6a06ac68c627d`** — **the identical commit our strata-custom-2 pins** (`third_party/ggml/VERSION.txt` matches byte for byte).
- **The delta vs upstream is exactly latent-MoE support** for Edge0 145B/120B (EDGE0.md "Changes from upstream Strata"): NVFP4 + Q3_K latent experts (A), per-layer D/U in Q8/Q4 (`STRATA_LATENT_DENSE_FMT`), 1792/1280 latent dims, expert group labels, fused prefill/decode kernels, CPU/PCIe share of non-resident expert work, tensor-name aliases for the native loader, plus Windows-Arm64 build fixes. Removed: sycl/, apps/, docker/, spark/, integrations/, upstream bench results.
- Uncommitted-at-import files are hash-listed in [edge0/IMPORTED_UNCOMMITTED.txt](https://github.com/Edge0-AI/Edge0/blob/main/edge0-strata/edge0/IMPORTED_UNCOMMITTED.txt): ~38 files, essentially all `lat_*` (include/strata/prefill/lat_group_tables.hpp, lat_pseudo_groups.hpp, lat_q3k_{down,gu,swiglu,fused}.hpp/.cu, src/prefill/lat_*.cpp, src/core/latent_dense.cpp).
- **What it wires**: engine = Strata; pack format = strata pack index v3 (+ native experts v6); tokenizer = folder-exported Qwen BPE; attention = upstream QSA kernels (`qsa*.cu`, `native_qsa*.cu` — inherited, not fork-added); PLE = upstream `ple.cu`/`ple_reader.cpp` + `--ple-gguf` fp8 streaming; MTP/spec = upstream spec machinery + `--mtp ./mtp` dir; NVFP4 = llama.cpp-lineage mmq plus **fork-side `mmq_nvfp4_w4a4.cu` / `mmq_nvfp4_w4a8.cu`** (W4A4 = FP4 tensor-core path) and `nvfp4_avx2/avx512` CPU kernels for the CPU share of expert work.
- Target: upstream Strata, not another fork — launch contract via `edge0/models/edge0-145b.json` (engine template, `--pack/--native/--ple-gguf/--expert-profile/--mtp/--kv int8/--max-context 131072`), started by `edge0-infer` (a separate C++ app; OpenAI+Anthropic endpoints; per [edge0-infer/docs/edge0-145b.md](https://github.com/Edge0-AI/Edge0/blob/main/edge0-infer/docs/edge0-145b.md): concurrent requests queue, decode not bit-reproducible, contract version 5).
- The latent core is small and clean: [include/strata/latent/latent_moe.hpp](https://github.com/Edge0-AI/Edge0/blob/main/edge0-strata/include/strata/latent/latent_moe.hpp) + [src/latent/latent_moe.cpp](https://github.com/Edge0-AI/Edge0/blob/main/edge0-strata/src/latent/latent_moe.cpp) (5.3 KB + 3.7 KB): `Geometry{H=2560, ELL=1792, I=640, G=8, E=512, K=10}`, host `build_plan` groups routes per expert, `run_layer` = D (Q8 mmvq) → quantize q8_1 → `native_expert_grouped` (NVFP4, `native_expert_layout(40,40,1792,640)`) → per-group U (Q8 mmvq) → combine. "The module only launches kernels, so it can be dropped into the existing verify/cache path without changing buffer ownership" (hpp comment).
- Engine techniques worth stealing regardless of adoption: prerouter = **prediction-as-routing** (per-layer head predicts next layer's routing one token ahead; staged set ≡ routed set; recovery LoRA served unmerged) — the AutoArk paper's core; disjoint GPU/RAM expert caches (no duplicate copies, `--resident-experts`/`--resident-budget-gib`); doorbell verify path + all-resident zero-doorbell path; `--pcie-mode dma --pool-workers 24` streaming; SSD mmap expert tier (`--mmap-experts`).

## 4. Fit math on our box (9950X3D, RTX 5090 32 GB sm_120, 184 GiB RAM, ~50 GB/s DRAM)

- **Expert pool: 47.79 GiB ≪ ~150 GiB budget** — 32%. Both builds together (Q3_K 40.81 + NVFP4 47.79) = 88.6 GiB would still fit; even the whole 105 GiB repo fits in RAM with PLE locked in RAM.
- **VRAM (32 GiB)**: fixed footprint ≈ skeleton 5.58 + MTP ~0.8 + verify/draft buffers ~0.45 + D/U device buffers + KV int8 32K resident 1.55 GiB (card-attested per README flag table) ≈ 9–10 GiB → `--expert-cache auto` leaves **~20 GiB of expert slots ≈ 45% of the pool resident** (vs ~14 GiB on their 24 GB card). 
- **Host RAM**: experts 44.29 + latent_dense_q8 3.49 + dense pool 1.43 + MTP 0.77 + skeleton cache + KV pinned ≈ 55–60 GiB with PLE on `--ple-io direct`; +47.7 GiB if PLE in RAM → ~105 GiB. Both fit 184 GiB.
- **Bytes/token (worst case, no cache)**: routed 10 × 1.935 MB × 48 ≈ 0.93 GB + shared 0.09 GB + skeleton active ~25 MB + D/U rows ~50 MB ≈ **~1.1 GB/token**; at 50 GB/s DRAM: 22 tok/s floor, 45 tok/s at 50% hit, ~75 at 70%. With spec-4 (their agent-decode 98.3 tok/s on a 24 GB card implies ~30 raw) our +8 GiB VRAM and +40% RAM cache should land **at or above their attested 98.3 agent / 79.6 chat tok/s**; prefill 3165.7 tok/s @16K is compute-bound, expect ≈ same. [inference — derived from attested 24 GB numbers + cache arithmetic]
- **Quality vs our lanes**: self-reported ≥ DeepSeek-V4-Flash-0731 class (our dsv41 lane's family) on agentic, ≈par knowledge; at/above its own claimed base on agent tasks only. vs M3.1 (428B/23B active): M3.1's quality ceiling is presumably higher (2.3× active params) but **no strata-servable artifact exists** ([[2026-11-14-minimax-m31-fit]] verdict: every path fused or custom-VQ + MSA attention port); Edge0-145B is **strata-servable today** on their MIT engine, needs only the latent delta to move into ours.
- **Tokenizer**: `pre=qwen35`, gpt2 BPE — inside our per-family pre-tokenizer machinery; expected near-zero work. [inference]
- **Engine work estimate for strata-custom-2** (delta audit vs our tree: no `lat_*` files, no `STRATA_LATENT_*`, no labels.bin; expert_layout.cpp knows native-experts v3/v4 and type code 42 but not v6/type-40):
  1. native_experts v6 parser + type-40 NVFP4 record layout in `expert_layout.cpp` — small/medium.
  2. Latent layer module (the 9 KB hpp+cpp reference + `lat_*` kernels) + labels.bin loader + 8-group D/U routing — medium; the reference drops into the existing verify/cache path by design.
  3. `--ple-gguf` fp8 table streaming — PLE kernels/reader already inherited in our tree (`ple.cu`, `native_ple_postops.cu`, `ngram/ple_reader`) — small.
  4. MTP dir loader adapter onto our existing DSpark/MTP drafter machinery — medium.
  5. Zero attention port (QSA + GDN + HC are upstream Strata = our base, already serving qwen3.8-flash-next-class archs upstream; Edge0 added only latent MoE). **This is the whole reason the estimate is days-not-weeks.**

## 5. Verdict vs current adoptions

**ADOPT (fast lane); watch M3.1 VQ for the quality ceiling.**

- Immediate path: build edge0-strata per EDGE0.md (CUDA 13, `CMAKE_CUDA_ARCHITECTURES=native` → sm_120), download the 103 GiB NVFP4 lane, run on their MIT engine day one. Simultaneously port the latent delta into strata-custom-2 for our scheduling/serving stack.
- vs [[2026-11-14-minimax-m31-fit]] (M3.1 VQ = #1 pending adoption): Edge0-145B wins on servability-today (per-expert pack + engine + MIT license), pool cost (47.79 vs 111.3 GiB resident), bytes/token (10.12B vs 23B active → ~2.3×), and license (Edge0 CLM 1.0 permits internal/commercial-output use; MiniMax Community needs attribution, also workable). M3.1 keeps the quality ceiling; its blocker remains GVQ kernels + MSA port.
- vs our DSv4.1 lanes: comparable quality class (self-reported vs V4-Flash; V4.1 itself likely ≥), materially cheaper serving footprint; the PLE+prerouter+latent machinery is also a source of portable techniques for our lanes regardless of adoption.
- Risks: publisher-asserted base (no training-source verification); 3-day-old release (single repo, no independent evals; the only third-party derivative is a CMF copy); active-param discrepancy (6.6 vs 10.12B) unresolved; Edge0 license bars commercial *service* use without a written license; decode is not bit-reproducible; concurrency queues (single-tenant serving).
