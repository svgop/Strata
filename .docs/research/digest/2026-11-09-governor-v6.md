# Governor v6 + the phased clock falsifier — 2026-11-09

## Verdict (read this first)

**v6 is built, smoke-tested, and NOT installed; deployment is gated on the phased falsifier
below, whose clean-box question is OPEN** (the 13:04 mem-pin run was contaminated — armed
hugepage pool + midday desktop load — and is void). v6 is the v2-refined regime: while an
engine LISTENS, hard-pin SM 3135 + MEM 14001 (`-lgc 3135,3135 -lmc 14001,14001`); on engine
exit (GRACE 45 s) release to DVFS. **No quiet timeout, no mid tier** — v2's demotion (the
measured 1780 MHz plateau, ~30% lane loss) is structurally absent: there is no pinned-LOW
state for a burst to enter from. All v4/v5 guardrails are kept byte-identical (watchdog
dead-man, `-i 0`, event-reason guardrail, thermal shed 83/78 C, port contract,
SUPPORTED_CLOCKS ban, SIGHUP reload). `SM_PIN`/`MEM_PIN` both default **1**; both `0` =
exact v4/v5-range behavior. **Pre-registered decision rule: pin phase ≥ +8% solo (probes
2-3 mean) with no lane worse ⇒ install v6 as standing; otherwise v5-range stands and the
clock question closes permanently.**

## 1. Regime table and why the plateau cannot recur

| State | v2 (Nov-6 record era) | v6 |
|---|---|---|
| Engine listening, processing | hard pin 3135/14001 (util≥10% or power≥150W detected by poll) | hard pin 3135/14001 (unconditional — no detection in the serving path) |
| Engine listening, quiet >30 s | **hard pin 1800/7001 — the banned defect**: bursts from gaps ran 1777-1792 MHz at 94-98% util for seconds until the 3 s poll re-pinned (~30% lane loss) | **same pin as processing — no demotion exists** |
| Engine gone 45 s | release | release (unchanged) |

The v2 plateau was a property of the DEMOTION (pin-LOW + poll lag under a hard lock, which
blocks boost above the pin). v6's only pin is at MAX: a burst arriving at any moment of the
residency enters at 3135/14001 already held (575 W cap trims sustained SM to ~2830-2955
exactly as it did through the whole v2 era — Nov-7 dmon proof, pviol=1). The `ACT_UTIL` /
`ACT_POWER` / `IDLE_GRACE` machinery is gone from the loop entirely; `gpu_read` still reads
only temperature + event-reasons (guardrail/shed), never utilization.

Named cost: quiet-listen holds pinned max (~70-110 W vs 56-58 W under the v4/v5 range;
mem 14001 static + SM pinned while the engine idles resident). The shed path (83 C shed /
78 C resume) covers the thermal tail; 40+ C of margin exists at current ambient. This is
the deliberate price of "listen = serving-state, zero transitions".

Arming gap unchanged: the pin lands within POLL (3 s) of the port binding; model load runs
before the port binds, so no measured window touches the gap — true in every version.

## 2. Diff vs v5 (code lines; comments excluded from the count)

`engine_running`, `gpu_read`, `wd_ping`, the TERM/INT trap, and the entire state machine
(shed/guard/gone counters, sleep POLL, `systemd-notify --ready`) are byte-identical to v5.
Changes:

1. `SM_PIN=1` default added beside `MEM_PIN=1` (both before the sysconfig source, so
   `/etc/sysconfig/strata-gpu-lock` overrides).
2. `mem_mode()` → `clock_mode()`: prints `HARD PIN 3135 sm / HARD PIN 14001 mem` or
   `range 1800-3135 sm / range 7001-14001 mem` (per-branch) in every journal line.
3. `apply()` case `floor` → `pin`: SM gains the branch v5's MEM had —
   `SM_PIN=1 ⇒ -lgc $SM_MAX,$SM_MAX`, `SM_PIN=0 ⇒ -lgc $SM_FLOOR,$SM_MAX` (v4 behavior);
   MEM branch unchanged from v5. The `off` case is untouched.
4. HUP trap re-applies with `SM_PIN=${SM_PIN:-1}` added.
5. Banner/log language: `watching v6 (… no mid tier — v2's 30s-quiet demotion is removed …)`,
   `engine listening — $(clock_mode) (no mid tier: bursts enter at the pinned max)`,
   `engine gone 45s — clocks released (DVFS)`.

Smoke evidence (this pass, DRY=1, no GPU state written, fake `nc -l 8080` listener):
`bash -n` clean; branch matrix all green in the journal —
- shipped file + standing sysconfig (SM_PIN default 1, MEM_PIN=0):
  `watching v6 (HARD PIN 3135 sm / range 7001-14001 mem …)` → `engine listening — …` (16:27:54)
- throwaway copy, sysconfig source neutralized (1/1): `watching v6 (HARD PIN 3135 sm /
  HARD PIN 14001 mem …)` → `engine listening — HARD PIN 3135 sm / HARD PIN 14001 mem …` (16:28:17)
- 0/0 copy: `watching v6 (range 1800-3135 sm / range 7001-14001 mem …)` (16:28:17)
- TERM trap: `service stopped — clocks released` (16:28:39). One cosmetic defect found and
  fixed during smoke ("HARD PIN HARD PIN" doubling in the listen line).

**Config-law caveat the install must honor: `/etc/sysconfig/strata-gpu-lock` owns
`MEM_PIN` — an env-passed `MEM_PIN=1` does NOT survive the source.** The standing sysconfig
carries `MEM_PIN=0`; installing v6 without flipping that line runs a SM-pin/mem-range
HYBRID, which is neither v6's design nor v5-range. The install block includes the sed.

## 3. The phased falsifier (no install; clean box; one engine boot; A/B/A)

Why stop-first: the running governor re-applies its own regime on its 3 s poll and releases
on every transition — a manual pin is fought within one tick. `systemctl stop` runs the TERM
trap + `ExecStopPost` (both release), giving a clean slate for the manual pin. Note the
full SM+MEM pin is NOT producible via `systemctl reload` on the installed v5: v5's SM
branch is range-only — that governor cannot express phase B, which is exactly why v6 exists
as a new file.

Clean-box preconditions (the 13:04 contamination lesson): hugepage pool RELEASED
(`/proc/sys/vm/nr_hugepages` = 0 — the released-pool config is the one that read
+0.3/+7.1/+10.6% vs the leg-0 anchor), load < 2, no Chrome-class desktop batch. If the pool
is armed or load is high: reschedule, do not run — that is precisely the void run.

The engine boots ONCE and stays up across all three phases (removes the fresh-boot/prewarm
race the Nov-09 audit convicted); each phase is 3 probes, probe 1 warm-in, **probes 2-3
scored** (the battery convention). 60 s settle after each regime flip.

**Predicted windows (pre-registered, from the 12.27 vs 0.7 alternation):** the deficit
lives where the GPU-reach wait lives. Pair-class windows carry CUDA0 GPU-reach wait
8.60-9.86 ms/window in the E1 era vs 11.65-12.43 ms today (residency digest buckets and
matched-leg quotes; the sweep's extra5 line reads `GPU wait 12.27`), while solo-class
windows carry only ~0.45-0.7 ms — reach (VRAM expert-weight reads) is the
memory-bandwidth-bound segment and barely exists on solo. Two regimes:
- **Sustained-only bound:** range sustains MEM 13801, pin holds 14001 ⇒ +1.44% bandwidth ⇒
  ≤ -1.4% on the reach segment ⇒ pair ≈ +1.0%, solo/conc ≤ +0.4%. If this is the whole
  story, nothing clears the rule.
- **Burst-ramp hold (the hypothesis under test):** released-state mclk floats across bins —
  observed live this pass: released DVFS read MEM 13801 at 16:2x and 7001 twenty minutes
  later, desktop-only load — so a burst entering under the range pays whatever bin the card
  holds plus the ramp. If the pin restores E1-class reach (11.65 → ~9.9 ms on a ~17 ms
  pair window; matched-leg bound 12.43 → 8.60): pair +9-13%, solo +2-8% (the +2.0 ms
  solo-class run residual rides partly on VRAM-hit traffic, 19.58-39.10 reads/layer-window).

**Decision rule (pre-registered, verbatim): pin ≥ +8% solo with no lane worse ⇒ install v6
as standing; else v5-range stands and the clock question closes permanently.**
Boundary named in advance: the mechanism's biggest lever is PAIR (reach-bound), while the
rule keys on SOLO — the lane the 233.1 record was set on. A pair-only hold (+8-13% pair,
solo +2-7%, no lane worse) is documented as "mechanism held, rule not met": v5-range stays
standing under the pre-registered rule; that outcome is a finding, not a veto to relitigate.

Validity gate: phase C (back to range, same boot) must land within ~±3% of phase A. If C
drifts >5% from A, the box moved during the run and the A/B delta is untrustworthy — re-run.

```bash

cat /proc/sys/vm/nr_hugepages                       # MUST print 0 (released pool) — else reschedule

systemctl is-active strata-gpu-lock                 # expect: active
journalctl -t strata-gpu-lock -n 1 --no-pager       # expect: watching v5 (… mem range 7001-14001 …)

# ---------- 1. ENGINE UP (one boot for all phases; port 8081; prewarm-gated) ----------

( nohup ./launch-custom-iq3s-8081.sh > campaign/results/clkfalsifier-boot.out 2>&1 & )
for t in $(seq 1 100); do curl -s -m 3 http://127.0.0.1:8081/health >/dev/null 2>&1 && break; sleep 3; done
for t in $(seq 1 60);  do grep -aq "page cache warm in" campaign/results/clkfalsifier-boot.out && break; sleep 3; done
sleep 45
before=$(wc -l < logs/custom-iq3_s.log)
tail -n +$before logs/custom-iq3_s.log | grep -aE "the expert complement:|memfd, populated|store mapped|ARENA PAGES" | head -4

# ---------- 2. PHASE A — v5-range baseline (no sudo; the service owns the regime) ----------
for i in a1 a2 a3; do python3 campaign/probe-lane.py --port 8081 --label "clkA-$i" --short-n 6 | tee -a campaign/results/clkfalsifier.log; done
nvidia-smi --query-gpu=clocks.sm,clocks.mem,temperature.gpu,power.draw --format=csv,noheader | tee -a campaign/results/clkfalsifier.log
# witness A: SM 2677-2962 float, MEM ~13801, ~40 C

# ---------- 3. PHASE B — FULL HARD PIN (the sudo block; stop-first or the service fights) ----------
sudo systemctl stop strata-gpu-lock
sudo nvidia-smi -i 0 -lgc 3135,3135
sudo nvidia-smi -i 0 -lmc 14001,14001
nvidia-smi --query-gpu=clocks.sm,clocks.mem --format=csv,noheader
# ^ MUST print "3135, 14001" — if not, run the ABORT line from §5 rollback and stop here
sleep 60
( nvidia-smi dmon -s pucvmet -c 30 -d 1 -o T > campaign/results/clkB-dmon.txt & )   # sustained-clock witness
for i in b1 b2 b3; do python3 campaign/probe-lane.py --port 8081 --label "clkB-$i" --short-n 6 | tee -a campaign/results/clkfalsifier.log; done
nvidia-smi --query-gpu=clocks.sm,clocks.mem,temperature.gpu,power.draw --format=csv,noheader | tee -a campaign/results/clkfalsifier.log
# witness B: SM pinned (power-capped sustained ~2830-2955 in the dmon file), MEM 14001 flat
sudo nvidia-smi -i 0 -rgc
sudo nvidia-smi -i 0 -rmc
sudo systemctl start strata-gpu-lock
journalctl -t strata-gpu-lock -n 1 --no-pager       # expect: watching v5 banner again
sleep 60

# ---------- 4. PHASE C — control, back to range (no sudo) ----------
for i in c1 c2 c3; do python3 campaign/probe-lane.py --port 8081 --label "clkC-$i" --short-n 6 | tee -a campaign/results/clkfalsifier.log; done

# ---------- 5. SCORE (probes 2-3 mean per phase: skip *_1 lines) ----------
grep -E "=== PROBE|M1 single-stream|M2 pair|[0-9]+-conc" campaign/results/clkfalsifier.log
# solo  = M1 lines;   pair = "M2 pair" lines;   conc = "M2 6-conc" lines
# rule: mean(clkB-b2,b3 solo) >= 1.08 * mean(clkA-a2,a3 solo)  AND  B pair/conc >= A pair/conc
#        -> install v6 (block 6).  Anything else -> v5-range stands; clock question CLOSED.
# validity: mean(clkC-c2,c3 solo) within ~±3% of A — else re-run (box drift >= effect).
```

## 5. Rollback (each line exact)

```bash
# ABORT mid-phase-B (anything looks wrong): release and hand the regime back to the service
sudo nvidia-smi -i 0 -rgc; sudo nvidia-smi -i 0 -rmc; sudo systemctl start strata-gpu-lock

# SOFT (after a v6 install, back to v5-range behavior without a file move): sysconfig owns
# the pins — env cannot override it, and a later-deleted line needs a restart to re-anchor
echo 'MEM_PIN=0' | sudo tee -a /etc/sysconfig/strata-gpu-lock
echo 'SM_PIN=0'  | sudo tee -a /etc/sysconfig/strata-gpu-lock
sudo systemctl reload strata-gpu-lock             # HUP re-applies; restart if the engine is down

# HARD (exact standing state of 2026-11-09: v5 script + range regime)
sudo cp /home/svg/LLM/strata-custom-2/campaign/strata-gpu-lock-v5 /usr/libexec/strata-gpu-lock
sudo sed -i 's/^MEM_PIN=1$/MEM_PIN=0/' /etc/sysconfig/strata-gpu-lock
sudo systemctl restart strata-gpu-lock
journalctl -t strata-gpu-lock -n 1 --no-pager     # expect: watching v5 (… mem range 7001-14001 …)
```
