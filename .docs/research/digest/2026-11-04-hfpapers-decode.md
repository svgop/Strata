### 1. SpecPilot — lossless W12 weight format + tree/TLV verify on hybrid GDN targets [FULL]
**URLs:** https://huggingface.co/papers/2611.02501 · https://arxiv.org/abs/2611.02501 (HTML full text verified)
**Hardware:** H100 SXM5 + RTX PRO 6000 Blackwell **sm_120** (1.51 TB/s measured) — our 5070's arch family. SGLang v0.5.20. Targets: Qwen3.8-27B (**hybrid recurrent/GDN**), Muse-Glimmer-30B, Qwen3.5-4B, Gemma-4-12B. Drafters: DFlash2, DSpark, EAGLE-3.
**Mechanism (all lossless, all discovered by a ceiling-guided agentic loop, all compose):**
- **W12**: per-channel 16-binade exponent window; weight = sign + 4-bit exponent offset + 7 mantissa bits = 12 bits; out-of-window/zeros/denormals restored exactly via sparse per-channel escape list. Averages 12.01–12.02 bits/weight across 8 dense models from 6 families (escapes < 1.3e-4 of weights). Qwen3.8-27B converted layers 44.67 → 33.58 GB. Nested 8-bit view (first two-thirds of each record) is free for low-precision passes. AR GEMM gain 1.19–1.28x at bs1, 1.13–1.20x at bs32 (weight-bytes-bound products only). Promoted at 1.076x in paired spec runs; layout/edge-calibration refinement +1.015x.
- **Best-first tree verification for hybrid targets**: stock parallel drafters verify a single chain and ignore ranked alternate candidates — exact replay on DFlash2 lattices shows the unused candidates would roughly double accepted tokens per step. Tree scores each edge by log-softmax of the drafter's selector score given its parent (a tree that ignores draft-token conditioning accepts half the tokens). N=32 nodes, depth 15, drafter runs 16 positions (2x trained block). **GDN state without snapshots**: recompute state along each root path from the committed state (path-verify kernel); commit kernel replays the accepted path into all 48 GDN layers, bit-exact to stock on chains. **WY verify kernel** (TreeWY-style) turns the chain of rank-one delta-rule updates into matrix products solved for all paths at once on tensor cores; FP32 state split into three BF16 parts representing all 24 significand bits exactly, FP32 accumulation, within 1 BF16 ulp of the path kernel. Runs unchanged on DSpark lattices (Markov head scores adjacent pairs). Tree: 1.065x; GDN WY kernels: 1.030x (paired runs).
- **Two-level verification (TLV)**: Q pass over the 8-bit view nested in W12 checks the draft tree, returns the argmax-matching path + bonus token as chain C, no KV/state update; drafter re-drafts from end of C, best-first subtree truncated to N−|C| nodes attached; one exact pass over full W12 verifies the combined 32-node tree; only the exact pass accepts → lossless. Q pass matches exact top-1 at 98.7% of positions, zero extra model copy. RTX PRO 6000: TLV + split-KV attention = 1.147x paired gain.
- **Batching (lossless row selection)**: shared node budget across requests (192 nodes @ 24 requests, sits on a target-GEMM tile plateau) — with DSpark accepted 6–14% more tokens than equal-size per-request trees; per-request drafter block 16/12/8 chosen on GPU from recent acceptance + draft confidence (1.040x); prompt admission into the verify step so one weight stream serves prompt+draft rows.
**Measured end-to-end:** speedup over AR: stock 4.46x → 10.87x single request; 1.94x → 3.93x batched. 1.84x faster than DDTree (H100, single request). Qwen3.8-27B batched BF16: 5.94x @ 6 requests. Token forcing (stock-calibrated divergence test) passed by every final system — no quality loss by construction and by test.
**Quality cost:** zero (lossless; only rounding-path changes, both within exactness bounds).
**Verdict: TRANSFERS — top priority for Engine A.** Moves acceptance×window (tree on unused drafter candidates — our MTP+lookup drafter at 88–94% acceptance leaves the same idle-candidate headstock), GPU ms (W12 −25% GPU-resident weight bytes; WY GDN tree kernels), and the verify-window economics (TLV raises effective accepted-tokens per exact pass at the same 8–12 row cap). Engine B caveat: W12 needs BF16/FP16 source exponents — B is already 1.75–2.31 bpw, so W12 applies to A's GPU-tier weights and LM head only; B's dspark lattice still feeds the best-first tree builder unchanged.

### 2. Channel-selection reader — read only ~13–18% of routed-expert weights [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-28 (2610.37386) · https://arxiv.org/abs/2610.37386 (HTML full text verified)
**Hardware:** RTX PRO 6000 Blackwell (Triton kernels, vLLM), plus A6000/4xA5000/4x3090 panels. Models: Qwen3-30B-A3B-Thinking, Gemma-4-26B-A4B, Qwen3.5-35B-A3B, OLMoE, DeepSeek-V2-Lite, Moonlight.
**Mechanism:** at interactive batch sizes MoE decode latency = reading routed-expert weights. Channel selectors score intermediate channels and read only the top ones. Findings: (1) calibrated thresholds do not hold their read budget (18% budget actually reads 12.9%; drift in all 72 runs); (2) a top-k keep rule needs no calibration data and matches/beats the threshold version in 40/43 same-score comparisons at 13% and 18% budgets (all 23 generation tasks); (3) calibrated thresholds cause repetition-loop collapse on Gemma 4 long reasoning (cliff behavior). Their reader: rotated ternary sketch of weights screens channels (~7% extra storage), exact top-k selection, low-rank map of the down projections recovers skipped channels.
**Measured:** MoE blocks 1.90x faster at 17.8% reads on one RTX PRO 6000 in optimized vLLM (Qwen3-Thinking; MoE block was 18.3% of whole-model traffic — fixed kernel-launch cost eats part of the byte saving at batch 1); whole-model 1.72–1.88x at batch 1; batch 128 falls to 1.00–1.24x (channel sets grow with batch). Serving capacity: 3.3–4.3x more users at 100 tok/s under 8K–32K context.
**Quality cost:** approximation, not lossless. Held at 13–18% reads vs full model on GPQA-Diamond/IFEval/MMLU-Pro; repetition-loop risk below that; recovery map and screen storage +7–9%.
**Verdict: TRANSFERS to Engine B, gated on one QC re-test.** On our lane (pure DRAM-bytes GEMV, no launch-tax floor) the byte ratio converts more directly than on GPU: 13–18% weight reads + ~7% sketch ⇒ potentially ~3–4x off the lane term. **Named conflict:** our falsified "neuron sparsity" — the difference is this reader's screen+exact-top-k+low-rank-recovery vs naive activation skipping; re-test only this design on the CPU pool (screen from token hidden state + ternary sketch of gate projections), not the falsified variant. Moves lane bytes (B's dominant term).

### 3. Specter — draft-lookahead expert management for offloaded MoE [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-21 (2511.14102) · https://arxiv.org/abs/2511.14102 (HTML full text verified). Code: github.com/wwwwwf/specter_asplos
**Hardware:** single A100-40GB + 24-core Xeon + 256 GB RAM, PCIe 4.0 x16 (31.5 GB/s H2D). Models: DeepSeek-V2-Lite, Qwen1.5-MoE, Phi-3.5-MoE at 16/24/32 GB GPU budgets.
**Mechanism:** the on-device quantized draft model preserves high-fidelity TARGET expert-activation patterns, giving multi-step lookahead over future expert usage for the whole verify window (they show same-token/early-layer route prediction yields only µs windows — insufficient vs ms-scale transfers; draft-window lookahead is the first window big enough to hide movement). Components: Speculative Inference Controller (hybrid-precision sharing — gates/attention FP16 because router logit perturbations flip top-k; draft depth K swept {2..32} by TPOT, best K=16/8/16); Predictive I/O Orchestrator (bandwidth-aware three-phase prefetch of predicted experts, per-layer planning); Streamlined Execution Engine (MoE draft kernel fusion, **cache-aware expert verification reordering**, async overlap); verification expert cache-residency manager on GPU.
**Measured:** 1.50x average (up to 1.88x) TPOT vs SpecMoEOff SOTA baseline, single request. Cache hit rate (predicted-routed experts resident before demand-load) beats reactive LRU substantially; single-prefetch-at-draft-checkpoint variants lose to continuous predictive prefetch.
**Quality cost:** none claimed for the system (lossless execution; draft is standard spec).
**Verdict: TRANSFERS to Engine B's lane scheduler.** Distinct from our falsified "prefetch on flat routing": the predictor is the drafter's per-window expert-usage forecast, not a flat-routing assumption. Our analog: dspark drafter predicts target expert set for its draft tokens → (a) sort/batch the CPU lane's reads by expert across the 6 sequences' verify rows (same-expert grouping raises row locality + TLB behavior), (b) pre-stage next-window experts during the GPU 7.2 ms window. Moves slack ms (fewer of the ~4 ms host-sync stalls) and lane bytes per useful token; hit-rate telemetry is directly measurable on our pool. PCIe-vs-DDR5 boundary: their transfer term is PCIe H2D; ours is CPU-side GEMV over DDR5 — transfer the scheduling/inventory mechanism, not their byte math.

### 4. JSSA — joint-subspace sparse attention, gather-free indexed kernel [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-15 (2610.19026) · https://arxiv.org/abs/2610.19026 (HTML full text verified)
**Hardware:** B200 decode-throughput panel (Qwen3-8B, Gemma4-26B-A4B, GLM-4.7-Flash at 32K/128K); large-scale validation on DeepSeek and GLM-5.2-class (700B) models.
**Mechanism:** learn a shared low-dim query-key subspace M by minimizing bilinear token-score preservation error (closed-form spectral solution; refining the exact objective adds nothing). Maintain K_proj = K·Mᵀ as a scoring-only auxiliary cache (FP8 variant); score the per-KV-head-group mean query against K_proj, select top-B positions **per KV head**, then attend directly from scattered locations in the full KV cache — a gather-free token-level indexed-attention kernel that handles distinct per-KV-head selections in the standard GQA layout (also covers hybrid sliding-window/global GQA and MLA). Token scoring reads all N projected keys; attention reads only B.
**Measured:** up to 6.43x decoding throughput vs full-KV at 128K context on B200 at KV budget B=2048; close to full-KV accuracy on LongBench/RULER where token-level competitors inflate generation length or fail architecture-dependently; at 700B scale reaches 96–99% of model-native DSA decode throughput with calibration only (no training).
**Quality cost:** near-full-KV (score-preservation objective beats key-only or query-only projections); calibration is cheap, FP8 scoring cache "negligible accuracy impact".
**Verdict: TRANSFERS to Engine A's 12 QSA layers at 262K.** Moves GPU ms on the attention segment of the serial attn→moe chain and cuts KV reads (on top of int8). B=2048 at 262K is a ~128x selection ratio with near-dense quality per their curve. Kernel work is ours (QSA layout is custom), but the GQA-layout indexed-attention design ports; our QSA scoring-cache adds bytes ∝ rank·N — trivial vs the KV reads it saves.

### 5. DLite — history-free drafting for agentic/long-context [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-19 (2610.23787) · https://arxiv.org/abs/2610.23787 (HTML full text verified). Code: github.com/SJTU-DAI-Sys/DLite
**Hardware:** H800 serving runs; targets Qwen3-4B/8B; baselines EAGLE-3, DFlash, DFlash2, DSpark, DFlow.
**Mechanism:** on agentic workloads (long, continuously evolving contexts) draft models lose up to 80% of acceptance length; draft KV maintenance measured at 10–20% of end-to-end inference latency (DeepSeek-V4 MTP in SGLang). DLite drafts with NO historical draft KV: a parallel backbone consumes the target's contextual hidden states directly and predicts locally around the current position; a lightweight sequential head restores intra-block causal dependency in hidden space (no vocab projections); two-stage training (isomorphic history-aware teacher bridge, then align to target).
**Measured:** acceptance length 2–6 across general/long-context/agentic workloads; up to +70% over DSpark; eliminates draft KV entirely.
**Quality cost:** none beyond standard spec (verified sampling); needs drafter training.
**Verdict: TRANSFERS to Engine A's draft path at 262K.** Our MTP+lookup drafters carry KV over the full context; at 262K that is draft-KV bytes + host bookkeeping inside the 9–16 ms windows, and acceptance degrades with context. DLite-shaped retrain of the draft head (feed target hidden states, local window only) removes the draft KV term and holds acceptance at depth. Moves slack ms + acceptance×window. Cost: one draft-head training run (Qwen3-4B/8B recipe exists).

### 6. Training-free MoE expert pruning with correct routing semantics [FULL]
**URLs:** https://huggingface.co/papers?date=2026-11-04 (2610.41366) · https://arxiv.org/abs/2610.41366 (HTML full text verified)
**Models:** OLMoE, DeepSeek-V2-Lite, Moonlight (+Granite router); paired, multiplicity-corrected tests.
**Mechanism:** pruning = mask + replacement operator. Holding the mask fixed: the dominant effect is the survivors' **gate scale** — renormalizing survivors' gates on routers trained without top-k renorm costs 0.8–8.5 points and flips operator rankings; routers trained with renorm prefer the trained scale at 50% pruning. **Tilted novice**: closed-form low-rank map of the pruned expert's input (rank-0 = MoNE's constant), +1.2–1.8% params, +3.45/+1.37 points over constant replacement at 50% pruning on OLMoE/Moonlight; stable across calibration draws; largely unchanged under 4- and 3-bit quantization. No single operator dominates (trained-scale rerouting best on DeepSeek-V2-Lite).
**Measured:** quality at 50% pruning per above; no speed numbers in paper (it is an operator study, not a system).
**Quality cost:** 50% pruning with the right semantics holds benchmark scores within study-reported deltas; wrong semantics (renorm mismatch) costs up to 8.5 points.
**Verdict: WATCH → cheap TRANSFER for Engine B's pool.** Combine with a routing-frequency mask: prune the least-hit experts in the 78–109 GB store; lane bytes fall with their traffic share; replacement via tilted novice (a tiny GEMV) keeps those tokens alive. Quant-robustness result matches our 1.75–2.31 bpw regime. Moves lane bytes; needs our QC gate on generation tasks (their own evidence: operator choice is model-dependent).

### 7. KV4-RL — INT4 KV + selective INT8 protection [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-15 (2610.14448) · https://arxiv.org/abs/2610.14448 (HTML full text verified)
**Hardware/workload:** RL rollouts (Qwen3-8B GRPO), paged INT4 attention with integer decode path, FP16 scale/offset, per-token/head INT8 side entries computed pre-rounding.
**Mechanism/numbers:** matched-workload replay shows KV quantization beats weight-only/W-A quant for decode-heavy phases; calibration-free INT4 KV + **INT8 protection of attention sinks (16 positions) and a recent-context ring** cuts sampler mismatch while keeping most of INT4's speed; 1.80x cumulative rollout speedup, 1.97x over final 50 iterations; INT4 history covers every position (no historical requant when a token leaves the recent ring).
**Quality cost:** bounded; sinks+recent protection is the fix for flat INT4 degradation.
**Verdict: SKIP as a new item — NVFP4-KV is already queued — but merge this refinement into it:** protect attention sinks + recent ring at int8, quantize the rest to 4-bit, keep per-token/head scales computed from source vectors before rounding. Moves KV bytes (the 12-QSA-layer read at 262K).

### 8. AKV — cache engineering for agents (drop / repos) [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-22 (2610.28577) · https://arxiv.org/abs/2610.28577. Code: github.com/thu-nics/AKV
**Mechanism:** agent-facing KV ops: `drop` (exclude selected cache entries from future attention without touching the trajectory or re-prefilling) and `repos` (rotate retained keys' position encodings so history reorganizes without recompute). Core finding: cache state is history-dependent — identical token prefixes yield different cache states under different op sequences, so **prefix matching is insufficient for correct reuse**; AKV engine co-design: radix tree with drop nodes, drop-aware eviction (a request's dropped KV may still serve another), segment-batch attention, restore path.
**Measured:** +27.7% task accuracy vs threshold-triggered summarization (agent benchmarks, Qwen3-30B-A3B class, SGLang); 1.18–1.2x output throughput; 1.51x P95 request latency; RSI-tuned policy −7.1% cost.
**Quality cost:** positive here (it replaces lossy summarization), but `drop` is attention-level eviction — quality depends on policy.
**Verdict: WATCH.** Our 93–94% prefix reuse assumes prefix-identity reuse; AKV adds a decode-side lever (shrink the ACTIVE set that attention reads at 262K while keeping the cached prefix valid) plus the first formal treatment of cache-state-vs-prefix mismatch — relevant the day we run multi-turn agent loops where turn-N edits invalidate turn-N+1 reuse silently. Moves GPU ms (attention reads) + prefix-cache correctness. Requires engine co-design; not a bolt-on.

### 9. Soft-MTP — fix the MTP training gradient [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-30 (2610.38331) · https://arxiv.org/abs/2610.38331 (HTML full text verified)
**Mechanism:** MTP cross-entropy gradient decomposes exactly into a KL self-distillation term (pulls each MTP head toward the model's own NTP distribution — the term that improves spec-decoding acceptance) plus a low-SNR residual that buries it. KL gradient-recovery trick: with a shared linear output head, recover the KL gradient exactly from the two cross-entropy gradients via straight-through routing — no vocab-sized logit matrices, compatible with fused CE kernels; one-line change; supports DeepSeek- and Meta-style MTP.
**Measured:** 167M–1.2B LLaMA-style pretraining, DeepSeek-style MTP, K=3 heads, self-speculative verify: acceptance length +1.8–2.2%, spec speedup +1.4–1.5% per scale, lower KL/TV to the NTP verifier at every scale; also better NTP perplexity and zero-shot accuracy.
**Quality cost:** none (improves both quality and acceptance).
**Verdict: WATCH (train-time).** Applies only when Engine A's draft layer is retrained (e.g., a DLite-shaped retrain) — fold it in then; a standalone retrain for +2% acceptance is not worth the run by itself. Moves acceptance×window marginally.

### 10. You don't need long context — compaction as a decode strategy [ABS + partial full text]
**URLs:** https://huggingface.co/papers/2611.05306 · https://arxiv.org/abs/2611.05306 (NVIDIA, Project Moonshot)
**Mechanism/numbers:** later tokens are costlier: measured decode-throughput disparity up to **7x** between 16K and 256K contexts on frontier open-weight models (r_M = T(256K)/T(16K)). Frequent compaction (down to single-action-per-context on SWE tasks) holds task accuracy across long-horizon/long-input suites; proposes semantic SSMs as the endpoint.
**Quality cost:** "little to no" on their suites; depends on compaction quality.
**Verdict: WATCH — operational, zero engine work.** Keeping working context ≤32K collapses our attention read and window costs at the product level; interacts with (not replaced by) our 93–94% prefix reuse — compaction invalidates long prefixes but the decode-side win at 262K dwarfs the re-prefill at these TTFT numbers (539 ms + 6.3K tok/s ⇒ 32K prompt ≈ 5.6 s, one-time).

### 11. N-Gram memories at 2-bit (CP codes) [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-20 (2610.21810) · https://arxiv.org/abs/2610.21810 (HTML full text verified)
**Mechanism/numbers:** Conditional Program representation: per-row short code + local scale + shared reconstruction program (Gaussian trellis, norm restoration, independently decodable rows); 2-bit codes lower output KL 41–63% vs 2-bit RTN; DeepSeek n-gram table 203 GB → 51 GB; lookup 0.190 ms (HBM) / 6.54 ms (pinned host DRAM over PCIe) per 48-row request on H200.
**Verdict: WATCH.** Direct port to our lookup drafter's tables: 4x table shrink → draft-path bytes fall; decode-cost per lookup is small but the tables are exactly this shape. Moves draft-path lane bytes.

### 12. SSA — stratified sparse attention (top-k + corrected residual sampling) [FULL]
**URLs:** https://huggingface.co/papers?date=2026-10-22 (2610.28441) · https://arxiv.org/abs/2610.28441. Code: github.com/skylight-org/SSA-Paper-Code
**Mechanism/numbers:** deterministic top-k retrieval + sampling of the residual with proxy-score inclusion-probability correction; generalizes top-k/top-p/hybrids. RULER-HARD, Ministral-3-8B, 50x sparsity: 81.8→84.2 (32K), 63.8→69.3 (128K), recovering 94%/85% of dense; up to 2.96x decode speedup over FlashInfer at 1M context with optimized kernels (GPU model unspecified in verified text — boundary named).
**Verdict: WATCH — second choice behind JSSA for the QSA layers.** Sampling adds quality headroom at extreme sparsity but its sampling step costs kernel work JSSA avoids; stackable idea (use proxy-score sampling on top of subspace selection if 262K quality dips).

### 13. ProVe — proposer-verifier role inversion [ABS]
**URLs:** https://huggingface.co/papers?date=2026-11-03 (2610.27815) · https://arxiv.org/abs/2610.27815 (abs page verified; full HTML unavailable — boundary named)

**Verdict: WATCH.** Mechanism interesting (one-pass block proposal by the target itself = our MTP layer's job, done better), but requires backbone fine-tuning we don't do. Revisit only if a future Engine A bake includes proposer training.
