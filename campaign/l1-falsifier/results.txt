QUESTION: does S1 (chunked) or S2 (scatter-promote) beat the 2.47 ms/row-class
row-serial replay by >=20x at n=4, B=6?

BASELINE: row-class replay window = 4 x 2470 us = 9880 us. 20x kill line = 494 us.

VERDICT: NO for every arm that moves full state. YES only for the index-select
commit (D1.2 pool-direct free-list), and its win is displaced into verify-time
checkpoint writes that erase it window-inclusive.

1. S2 index commit (pool-reserved free-list, FlashInfer state_indices form):
   MEASURED at full B=6: 2.95 us/window (1 launch, B*L index writes) = 3347x.
   This is the only measured >=20x. Caveat: honest ONLY in the pool-direct form
   where the next verify reads state via indices (SGLang D1.2); promoting into a
   canonical buffer costs a full gather (see 3).

2. S1 chunked commit (1 launch, state resident in registers, one r+w pass):
   B=6 arena (576 MiB) VRAM-gated by the live server (spec item 10 boundary;
   465 MiB free after context init). B=1/B=2 measured: 286 us (B=1, n=4) and
   572 us (B=2, n=4); achieved BW 704-760 GB/s. [proj] B=6 = ~1.72 ms/window
   (3x state-bytes, BW-stabilized) = 5.8x — under 20x.
   FLOOR ARGUMENT (gate-independent): any full-state commit at B=6 moves
   >= 2 x 576 MiB = 1.152 GiB -> >= 1589 us at the best measured BW (~760 GB/s),
   >= 674 us even at 5090 peak (1792 GB/s). The 494 us kill line sits BELOW the
   physical floor: ratio ceiling is 6.2x (realistic) / 14.7x (theoretical peak).
   No full-state-pass commit can ever hit 20x at n=4, B=6 on this box.

3. S2 gather commit (checkpoint[n-1] -> canonical state): same traffic class as
   S1 (r+w of full state), measured ~= S1 at equal geometry (B=1 n=4: 294 vs
   286 us). Same floor, same verdict: under 20x.

4. S2 window-inclusive (verify-time checkpoint writes + commit): the commit win
   is displaced into T x state checkpoint writes during verify (FlashInfer form,
   spec F1). Measured B=1 n=4 bf16 (naive 2B-store layout): 1905 us per 96 MiB
   slot-set -> x6 = ~11.4 ms at B=6, i.e. ~0.9x — WORSE than the 9.88 ms replay
   baseline window. Optimistic bound using the coalesced fp32-pattern BW

5. Synthetic anchor: our S0 row-serial replay runs ~313 us/row (B=1) and
