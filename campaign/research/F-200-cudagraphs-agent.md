# Research brief 4: CUDA graph / launch latency (agent, 2026-10-15) — 10 findings

Framing: 1,800 nodes × 9.5 µs ≈ 17 ms spacing vs H100 graph-replay FLOOR ~1.3 µs/kernel (Hazy Research) — we are ~7× above floor: mostly recoverable, not physics.

1. **Megakernel / persistent kernel** (Hazy Research "Look Ma, No Bubbles" 2025-05; Mirage MPK; Kog.ai MI300X) — whole forward in one persistent kernel, GPU-side interpreter, dependency counters; 78% of bandwidth at batch-1, ~2.5× vs vLLM H100, ~3.5× B200. CEILING (2-3× window). Incremental: per-layer-group megakernel cuts nodes ~4×.
2. **Vertical fusion to cut node count** (TRT-LLM piecewise graphs + torch.compile; FlashInfer arXiv:2501.01005 29-69% ITL) — fuse RMSNorm+QKV+RoPE, attention+residual: 35-44 → 12-18 nodes/layer → 1,800 → 700-900 nodes = **8-10 ms of spacing** at our 9.5 µs. Highest impact-per-effort.
3. **Device-side graph launch + tail launch** (CUDA 12.0+, cudaGraphInstantiateFlagDeviceLaunch) — a kernel launches the next graph; NVIDIA-measured >2× lower launch latency than host, CONSTANT in graph size (our 1,800-node graph is host-launch's worst case). Last kernel of window N tail-launches N+1. Pair with cudaGraphUpload. HIGH applicability, moderate effort.
4. **Conditional nodes: green field CONFIRMED** (IF nodes CUDA 12.3, WHILE 12.4; zero production uses in vLLM/SGLang/TRT/FlashInfer as of early 2026; ROCm parity open #6398) — IF gate can early-exit the verify tail when all k tokens accept (skip ~(k−accepted)/k of execution); WHILE = adaptive window depth. CAVEAT: no published dispatch-cost numbers — microbench the IF node on sm_120 first.
5. **Fence/doorbell hygiene = likely our dominant spacing tax** (arXiv:2511.15076 NCCL GPU-initiated networking; CUDA visibility refs) — __threadfence_system costs 0.5-2 µs; spin-polling globals in graph nodes burns SM issue and serializes launches. If 5-7 µs/node is fence/poll → 9-12 ms/window. AUDIT every node boundary: device-scope fences, doorbells only at window boundaries, let graph edges carry ordering. FIRST ACTION (cheapest).
6. **Look-ahead submission** (DuetServe arXiv:2511.04791; SET arXiv:2606.05495 — EVALUATED ON RTX 5090: host overhead relatively WORSE on Blackwell, 34.6% vs 29.8%) — pre-instantiated graphExecs with pre-updated metadata, submit N+1 while N runs; 1.15-1.44× demonstrated. Host-thread architecture change.
7. **Green Contexts** (Open-Infer blog; CUDA docs; DuetServe) — SM partitioning for decode+prefill co-location: ~34% H200, ~60% RTX 5070 Ti (consumer!). Converts prefill-waits-for-window into spatial overlap. Driver-API only, works on consumer Blackwell.
8. **Launch-completion edges** (cudaGraphKernelNodePortLaunchCompletion) — edge fires when upstream blocks LAUNCHED (not completed), zero kernel changes (unlike PDL which needs kernel-side trigger — why PDL was a no-op for us). 1-3 µs/edge on paper; cheap attribute sweep, hours.
9. **Multi-stream fork/join + node priorities inside one graph** (fully supported in capture; cudaGraphInstantiateFlagUseNodePriority) — co-run small GEMVs (QKV, experts) that underfill 170 SMs; event edge costs 1-2 µs — fork only where branches >5 µs each.
10. **Spec-graph coverage gap** (vLLM #36037, SGLang #19896) — nobody ships unified verify graphs with adaptive control flow; our one-graph-per-window is ahead of production. Strategic.

**Attack order: #5 fence audit (days) → #2 vertical fusion → #3 device/tail launch → #4 conditional nodes; #7 for prefill overlap; #1 megakernel as endgame.**
