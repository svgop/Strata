### 3.4 — NEW, NEVER-ATTEMPTED: context-n-gram draft source (prompt-lookup class) — band **0% (open-ended probes) to +5..25% (copy-heavy traffic) M1** [HYPOTHESIS from the external class; falsifier is free]

**Mechanism.** A second, model-free proposer that runs BESIDE the coupled MTP drafter: at each draft
position, hash the trailing n-gram (n ∈ 8..24, longest-match-first) against the live context
(prompt + emitted tokens); on a hit, **substitute the n-gram continuation for the MTP proposal
token** before it becomes the next draft row's input; on a miss, keep the MTP proposal. The verify
window, the exact-match contract, and the graphs are untouched — a wrong substitute costs exactly
what a wrong MTP proposal costs (one rejection), so the arm is **lossless by construction**. The
chain stays causal (substitution happens before the next row consumes the token). This is the PLD /
LLMA / REST class: vLLM ships it as a first-class proposer (docs.vllm.ai speculative-decoding,
"n-gram/prompt lookup"), SGLang likewise; the original PLD implementation reports 1.4-2.5x on
input-grounded tasks (github.com/apoorvumang/prompt-lookup-decoding); LLMA (arXiv 2402.02057,
Moonshot) and REST/REST-MLP (arXiv 2311.08252 / 2404.15028) are the paper lineage [CORROBORATED].
**Why it is never attempted here:** the engine's n-gram machinery (the 28.8 GB PLE engram) feeds
LAYER-1 INPUT rows, not draft tokens — T42-r3 verified "the draft layer contains no PLE module";
the ngram-mod long-key upgrade in the queue is about PLE keys. No token-level lookup proposer exists
anywhere in the tree [MEASURED-OURS, T42-r3 §4 + grep].

**Where it lives (cost anatomy).** The coupled serial draft loop: proposal tokens cross host at the
existing pinned staging (`h_tok_/h_out_`, mtp.cpp); the substitution site is the draft-row build in
`src/core/mtp.cpp` (chain loop) with the hash index maintained host-side over the session context
(the PLE-side hash machinery in `src/ngram/ngram.cpp:62-93` is a donor for the rolling hash). S ~
150-300 lines, env-gated `STRATA_NGRAM_DRAFT=1` (+ `_MINLEN`, `_MAXN`), default-off, zero graph
changes, exactness untouched (verify.cpp consumes whatever token the chain carries).

**Falsifier-first (the cheapest read on this entire board, zero boots):** an offline probe — take
the standing M1/probe corpora AND one day of real traffic, and measure P(the context contains the
true next 8-gram | position) with a 30-line script over the session logs. That number × C-band
directly prices the arm's ceiling per traffic class. GO criterion: probe-ceiling ≥ +3% on the
lane you want the record on. The honest expectation: **the standing probes are literary/open-ended
and will read ~0 — this lever is for real copy-heavy traffic (code edits, template answers,
