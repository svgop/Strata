# Deep brief 8: serving-loop scheduling (investigative-researcher, 2026-10-15) — 10 findings

1. **SHAPE-KEYED CUDA GRAPHS (vLLM pattern) = the root-cause fix for our 176 re-captures**: capture a discrete set of PADDED batch shapes; dispatch key = (num_tokens, num_reqs, uniform, has_lora) ONLY — slot/row identity lives in page tables/buffers, NOT in the graph. Slot rotation can never re-capture. We need ≤6 padded decode graphs + mixed-mode keys. Replaces the whole pre-capture/sentinel queue with a one-time startup capture. IMPLEMENT FIRST (prerequisite for everything else).
2. **Token-budgeted MIXED prefill+decode windows** (vLLM V1: phases removed, one step = decode rows + prefill chunk under a fixed token budget; SGLang --enable-mixed-chunk): ragged attention runs OUTSIDE the graph (piecewise capture). At 1-6 users: the 32k serial chunk stall becomes one ~1-2k-token chunk per window. vLLM V1 broad numbers: up to 1.7× throughput, 5× latency (cluster-scale upper bound).
3. **Admission is DISPATCH-bound, not bandwidth-bound (FastSwitch, arXiv:2411.18424)**: at 16-token block granularity, per-op cudaMemcpyAsync dispatch = 90-95% of transmission time; swapping = 59.9% of P99 even at 1 req/s. OUR 54.8-58.3ms waves vs a ~13ms raw-copy floor (0.73GiB at ~50-55GB/s) = the same 4× signature. Fixes: buddy-style contiguous block groups, C++ swap manager with CUDA-event tracking (no device syncs), sync every K dispatches so decode-stream copies preempt admission. 1.4-11.2× tail improvements.
4. **Layer-wise pipelined admission (Pensieve EuroSys'25)**: swap in KV layer-by-layer on GPU events; each layer's attention starts when its KV lands; swap OUT when free slots <25%. 1.14-3.0× vs vLLM/TRT-LLM. At 0.73GiB/slot: ~13ms amortized across the next window's layers ≈ near-zero visible stall.
5. **Cost-ranked retention + adjacent preallocation**: Pensieve V = recompute_cost/time_since_active, evict the LEADING end (cheapest to recompute under causality), +4.4pts hit vs LRU, −14.6% recomputed KV; CachedAttention: pre-RoPE storage (truncation never invalidates — hit −17.6..41.5% without it), queue-lookahead eviction window (86% vs LRU 58%); FastSwitch: swap out only contaminated segments (−53% blocks) + preallocate adjacent space for next-turn growth.
6. **Overlap scheduler (SGLang v0.4)**: CPU scheduler one batch ahead + events/streams — no device-wide sync anywhere; unoptimized engines spend "up to half their time on CPU overhead". Every cudaDeviceSynchronize forfeits the in-flight window. Replace ALL 14-30 waves with event-query polling on an admission stream.
7. **Conditional nodes (CUDA 12.8) = one graph, multiple layouts**: SWITCH on a device-side layout id / IF-guards skipping inactive rows; bodies fillable without parent re-capture (cudaStreamBeginCaptureToGraph). No cooperative kernels inside bodies; NO published overhead numbers — prototype behind finding 1, not a substitute.
8. **Match-ranked admission ordering (Mooncake)**: admit longest-exact-KV-match first, prefill by predicted cost — pure bookkeeping, TTFT-variance reduction at burst coalescence.
9. **TTL expiry for parked conversations** (agent tool-call waits; Continuum/CacheTTL): prevents zombie sessions churning the 49GB pool. Hygiene.
10. **Rejected with numbers**: CacheGen compression (saves <1.5ms at PCIe5 local; only for NVMe/disk tiers), InfiniGen selective paging (full-offload regime, accuracy knobs — unneeded at 6 slots).

**Sequence: shape-keyed graphs (1) → mixed windows (2) → event-based admission (3+6) → layer pipelining (4) → retention policy (5). Combined: TBT spikes during admits → ~one extra chunk-time/window; admission → raw PCIe floor. OPEN: 1-6-user SM-partition-vs-interleave crossover has NO published measurement — our own microbench would be first.**
