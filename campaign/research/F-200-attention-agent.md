# Research brief 1: attention/GDN kernels (agent, 2026-10-15) — 12 findings

1. **Row-grouped verify attention** (FlashInfer cascade inference — 31× shared-prefix decode; vLLM-metal RFC #465 — redundant KV reads in spec-verify; SGLang tree-verify) — treat the 6 concurrent rows as ONE multi-row query block (query_len=6) against the same block-indexed KV; every KV page gathered once per (head, block) instead of 6×. 4.4 ms → ~1.0-1.5 ms realistic. VERDICT: highest priority (= our T1.2, now production-corroborated).
2. **SpecSA** (arXiv:2605.19893) — adjacent verify queries select 50-90% overlapping KV blocks; group C adjacent queries per block, merge index sets on-chip, load unique blocks once with per-query masking (exact mode). Index construction is 45-56% of NSA-family kernel runtime → bypassing it is the dominant win. Up to 6.86× kernel, 1.45× verify stage. VERDICT: our exact shape; needs per-row block lists intersectable in smem.
3. **TMA Gather4 (TMALDG.Gather4) on sm_120a** (TRT-LLM blog15 DeepSeek-V3.2; vLLM #27542 confirms working on consumer Blackwell + CUDA 13) — loads 4 rows of a 2D tensor from scattered addresses coalesced into smem; replaces per-thread dependent pointer loads. TRT sparse MLA: +47% TPS, ~1.5× on the attention line. Our 4-token pages: gather a 4-page "super-row" or pad pages to 16+. VERDICT: strong fit — compile with -arch=sm_120a.
4. **cp.async.bulk.prefetch.L2 of next block** (arXiv:2504.06319, AAAI-26) — warp loads current KV block into registers AND issues non-blocking L2 prefetch for the next block-table entry (statically known). Attention kernel 1.84-2.15×, Stall-Long-Scoreboard −66-75%. Batch-6 working set at 3k depth ≈ 216 KB = trivially L2-resident on 128 MB L2. VERDICT: one-PTX-line retrofit, pair with #1.
5. **GVR temporal correlation** (TRT-LLM blog21, arXiv:2604.22312) — consecutive steps' top-k sets overlap 35-50%; warm-start from previous step's index, secant-search the threshold, refine in smem: 1.88× vs radix-select, 7.52% TPOT cut at 100k ctx batch 1; previous step's blocks are L2-hot. VERDICT: applies to our QSA indexer refresh.
6. **SageAttention int8 MMA** (thu-ml/SageAttention) — feed int8 K directly to IMMA tensor cores with per-block scales, V dequant fused in epilogue; 2-5× vs FA. Our KV is ALREADY int8 — we dequantize into a shuffle-bound scalar path today. sm_120 supports mma.sync s8. VERDICT: high fit; add per-page fp16 scales if absent.
7. **sm_120 attention recipe** (gau-nernst "FA for RTX 5090", 94.4% SOL) — mma.sync.m16n8k16, Q in registers, ldmatrix.x4 (+4.5 TFLOPs), XOR smem swizzle; KEY for us: with the m16n8 accumulator layout the S→P repack "requires no data movements across threads" — the mma fragment layout REPLACES our 12-shuffles-per-KV-cell dot with zero cross-lane traffic. VERDICT: the compute-inner-loop template for the new QSA kernel.
8. **FlashMoBA** (arXiv:2511.11571) — gather-and-densify sparse queries into smem, two-level tiling (logical sparse blocks outer, dense 64×64 tiles inner), fused Flash-TopK (routing was >70% of naive time). VERDICT: tile doctrine for our 4-page groups — group pages into logical 32-64-token blocks.
9. **NSA** (arXiv:2502.11089) — blockwise selection at tensor-core tile granularity + GQA head-group packing (one block load serves the head group). 11.6× decode vs FA2 at 64k.
10. **TRT-LLM blog15 extras** — (a) partition-based radix-select top-k 7.41× vs torch.topk; (b) SHORT-CONTEXT DENSE CUDA GRAPH: when selected set ≥ context depth, dispatch a separate dense graph — free win for short rows. VERDICT: audit if any QSA layer's top-k ≥ depth for our 3k-typical traffic.
11. **FA4 concepts** (arXiv:2603.05451) — conditional rescaling (rescale only if running max grew) + ping-pong producer/consumer warps; tcgen05 parts are sm_100-only. VERDICT: port the conditional-rescale + warp split only.
12. **GDN decode tile retune** (SGLang PR #17094, Qwen3-Next #18590) — raising BV 8→32 in fused_recurrent_gated_delta_rule gave ~10% e2e (2967→3266 tok/s B200, zero accuracy change); sibling kernels (_update, sigmoid_gating, kda) same retune; removing synchronous prefill→decode GDN state copies = next win. VERDICT: directly applicable — audit our recurrent kernel's B/V tiles + state copies.

**Cross-cutting:** #1+#2 (multi-row, merged sparse KV) and #3+#4 (TMA gather + L2 prefetch) are complementary; joint expectation: the 4.40 ms line → ~1 ms class.
